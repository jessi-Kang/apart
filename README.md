# 아파트 감별사 (가칭)

> "이거 진짜 있는 아파트야, AI가 지어낸 거야?"

화면에 아파트 이름 하나가 큼직하게 뜬다. **진짜** / **가짜** 중 하나를 누른다. 맞히면 연속이 쌓이고 틀리면 끊긴다. 창구(게임)에 들어가면 곧장 **무한 감별**이 시작되고, 같은 문제로 겨루고 싶으면 게임 안에서 **제N호 공식전**(그날의 10문제)을 신청한다. 결과는 판정 통지서로 나오고, 그 통지서를 이미지로 공유한다.

게임은 세 종류다. 감별 O/X, 이름 조립(힌트를 보고 실존 단지명을 조각으로 맞춤), 진짜 찾기(넷 중 진짜 하나 고르기).

## 개발 (`web/`)

Next.js 15(App Router) + TypeScript. 런타임 의존성은 Neon 드라이버 하나뿐이다.

```bash
cd web
npm install
npm run dev            # http://localhost:3000
npm run typecheck
npm run validate-pool  # 출제 풀 검증
```

구현된 것: 게임 3종의 무한 모드와 공식전(홈 대장의 공식전 열이 출전구), 시·도별 출제(담당 구역, 15곳), 서버 판정, 타이머, 조립 초성 힌트와 속도 점수, 누적 직급·연속, 판 단위 백분위 집계, 판정 통지서와 공유 이미지, 구글 로그인과 비회원 모드, 기록 클라우드 동기화, PWA 설치.

## 핵심 설계 원칙 (요약)

1. **게임은 닫히지 않는다** — 본편은 무한이다. 하루 한 번 제약은 공식전(랭킹전)에만 남긴다.
2. **가짜 이름 품질이 게임의 전부** — LLM 프롬프트 튜닝과 검수에 리소스를 가장 많이 쓴다.
3. **런타임 AI 호출 0** — 가짜 이름은 사전 배치 생성. 서버비 거의 0으로 시작한다.
4. **정답은 클라이언트에 내려주지 않는다** — 판정은 서버에서만 한다.
5. **콘텐츠 운영이 해자** — 출제 풀과 운영을 카피하기는 UI를 베끼는 것보다 훨씬 어렵다.
6. **로고는 절대 쓰지 않는다** — 브랜드명은 사실 정보로만 텍스트 사용. 지역 비하성 가짜 이름은 검수에서 걸러낸다.
