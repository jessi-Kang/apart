# 06. 게임 모드 확장

코어인 감별 O/X 하나로는 (1) 매일 같은 행동의 피로, (2) 릴스 소재의 단조로움, (3) 헤비 유저의 콘텐츠 소진이 온다. 같은 데이터(실단지 + 가짜 이름 풀)를 다른 각도로 써먹는 모드를 추가해, 데이터 파이프라인은 하나 유지하면서 게임은 여러 개처럼 보이게 만든다.

**설계 원칙 — 모드는 "많이"가 아니라 "계속 오게"**
1. **복귀 루프 없는 모드는 추가하지 않는다.** 모든 모드는 "내일 다시 올 이유"를 스스로 가져야 한다: 매일 갱신되는 문제(앵커형), 깨고 싶은 내 기록(기록 갱신형), 자정에 공개되는 결과(결과 대기형) 중 하나. 셋 다 아니면 재미있어 보여도 반려.
2. 모든 모드는 기존 데이터 풀(K-apt 실단지 + 검수된 가짜 이름)만으로 출제 가능해야 한다. 모드 추가가 콘텐츠 운영 부담을 늘리면 실패.
3. (개정) 초안에서는 "데일리 본편 하나 + 보조 모드"였지만, 실제로는 **무한이 본편**이고 게임 3종이 나란히 창구로 열려 있다. 하루 1회 희소성은 각 게임의 공식전에만 남긴다. 모드를 추가할 때도 이 구조를 따른다: 무한으로 상시 플레이 가능하고, 겨루고 싶은 사람만 공식전에 신청한다.
4. 모든 모드는 고유한 공유 포맷을 가진다.

## 모드 목록

### 1. 감별 O/X (1번 창구, 구현 완료)
실존 단지명이면 O, AI가 지은 이름이면 X. 무한 상시 + 공식전 10문제. 상세는 [02. 게임 상세 기획](02-game-design.md).

### 2. 이름 조립 (2번 창구, 구현 완료) ★
- **룰**: 힌트(위치·준공년도·세대수)를 보고, 섞여 있는 이름 조각에서 골라 실존 단지명을 순서대로 조립한다. 조각 풀에는 정답 조각 + 함정 조각(그럴듯한 펫네임 등)이 섞여 있다.
  - 예: 힌트 "서울 서초구 반포동 · 2023년 · 2,990세대" → 조각 [원 / 래미안 / 리버 / 베일리 / 노블] → 정답 `래미안 + 원 + 베일리`
- **왜 재미있나**: 감별이 "직감 게임"이라면 조립은 "지식 게임". 아는 단지가 나오면 쾌감이 크고, 몰라도 작명 문법(브랜드→지역→펫네임)으로 추리 가능해서 진입장벽이 낮다.
- **출제 데이터**: 실단지명을 토큰으로 분해(브랜드/지역/펫네임 사전 기반) + 함정 조각은 가짜 이름 풀의 조각 재활용. 전부 기존 파이프라인 산출물.
- **공유 포맷**: `🧩🟩🟩⬛ 조립 2/3` + 걸린 시도 횟수.
- **회차 구성**: 1일 10문제 + 무한 모드(랜덤 연속 출제, 연속 기록·평균 풀이 시간 기록). 문제당 제한시간 40초.

### 3. 진짜 찾기 4지선다 (3번 창구, 구현 완료) ★
- **룰**: 단지명 4개 중 진짜는 하나. 나머지 셋은 AI 작품. (역버전 "가짜 찾기"도 같은 엔진으로 가능)
- **왜 재미있나**: O/X보다 오답 유혹이 3배. 릴스 포맷과 완벽 호환 — 한 화면에 4개 띄우고 "진짜는 하나입니다"로 댓글 유도. 감별 O/X보다 영상 소재로 우월.
- **출제 데이터**: 실단지 1 + 같은 난이도 가짜 3. 조합만 바꾸면 되므로 출제 비용 0에 수렴.
- **공유 포맷**: `🎯 3연속 적중` 콤보 카운트.
- **회차 구성**: 무한 상시 + 공식전 10라운드. 콤보는 공식전·무한 공통. 라운드당 제한시간 15초.

### 4. 높거나 낮거나 (M3 후보)
- **룰**: 실존 단지 2개를 놓고 "세대수가 더 많은 쪽은?" / "더 최근에 지어진 쪽은?" 비교 (Higher-Lower 형식). 연속 정답 서바이벌.
- **왜 재미있나**: 이름이 아니라 메타데이터(세대수·준공년도)를 쓰는 유일한 모드. "헬리오시티가 9,510세대라고?" 류의 놀람이 공유 소재. 서바이벌 형식이라 최고 기록 경쟁이 됨.
- **출제 데이터**: K-apt 메타데이터 그대로. 가짜 이름 불필요.
- **공유 포맷**: `🏗️ 연속 12개 생존`.
- **리스크**: 특정 단지의 가격·서열 비교로 흐르면 안 됨. 비교 축은 세대수·준공년도 등 중립 지표만 사용 (가격·브랜드 서열 금지).

### 5. 빈칸 한 조각 (보류)
- **룰**: 실존 단지명에서 조각 하나를 가리고 4지선다로 채우기.
- **보류 사유**: 조립(모드 2)의 라이트 버전이라 고유한 복귀 루프가 없다 (원칙 1 위반). 우리 동네 모드의 출제 형식 중 하나로 흡수 검토만 남긴다.

### 6. 작명소 (기존 기획 유지, M3)
조각 조립으로 "가장 그럴듯한 가짜" 만들기 + 투표. 상세는 [02. 게임 상세 기획](02-game-design.md#6-1-작명소-모드). 조립 모드(모드 2)와 UI 부품(조각 타일)을 공유하므로 구현 비용이 함께 내려간다.

## 배치 전략 — 모드별 복귀 루프

| 위치 | 모드 | 복귀 루프 (내일 또 오는 이유) |
|---|---|---|
| 1번 창구 (무한 + 공식전) | 감별 O/X | **기록 갱신형 + 앵커형**: 최고 연속을 홈에 노출, 매일 새 공식전 |
| 2번 창구 (무한 + 공식전) | 이름 조립 | **기록 갱신형**: 최고 연속과 조립 점수 |
| 3번 창구 (무한 + 공식전) | 진짜 찾기 | **기록 갱신형**: 내 최고 콤보를 홈에 상시 노출, 깨러 오게 함 |
| 상시 (M3 후보) | 높거나 낮거나 | **기록 갱신형**: 서바이벌 최고 기록 |
| 2단계 | 작명소 | **결과 대기형**: 오늘 접수 → 자정 우승 발표를 보러 다시 옴 |
| 2단계 | 우리 동네 | 확산 목적 예외 (상시). 지역 평균 갱신이 약한 복귀 루프 |

**홈 화면 원칙**: 대장의 각 행은 이름 나열이 아니라 **상태를 보여준다** — 창구 칸에 개인 기록 꼬리표("무한 감별 · 최고 연속 12"), 공식전 칸에 출전 도장. 행 자체가 복귀 장치다. 미개설 창구는 점선 도장으로 기대감만 남긴다.

## 로드맵 반영

- **M1(완료)**: 감별 O/X, 이름 조립, 진짜 찾기 3종을 무한 + 공식전 구조로 구현. 초안의 "M3에 추가" 계획보다 앞당겨졌다.
- **M3**: 작명소, 우리 동네 개설.
- **M4**: 높거나 낮거나, 빈칸 한 조각을 지표 보고 선별 투입.

게임 화면의 원본 시안은 `design/sian-a-document.html`이고, 홈·결과·공유는 각각 `home2-a-ledger.html`, `result3-r1-verdict.html`, `share3-s2-receipt.html`이 확정본이다.
