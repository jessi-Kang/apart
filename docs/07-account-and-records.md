# 07. 서비스 플로우 · 계정 · 기록 시스템

시안 작업 중 확정된 방향을 기획으로 정리한다. 핵심 플로우는 **"게임을 고르고 → 플레이하고 → 결과를 공유하고 → 기록을 겨룬다"**의 4단계다.

## 1. 전체 서비스 플로우

```
[홈: 접수 대장] → [창구 진입 = 무한 세션] → [세션 종료: 판정 통지서] → [공유(접수증 이미지)]
      ↑                        ↘ (선택) [제N호 공식전]                        │
      └──────────── 기록 갱신하러 다시 오기 (연속·레벨·판 순위) ←─────────────┘
```

### 1-1. 홈 = 접수 대장
첫 화면은 인트로가 아니라 **게임 목록**이다 (확정 시안 `home2-a-ledger.html`).
- 순번 / 창구 / 공식전 3열 서식. 각 행이 게임 하나이고, 누르면 무한 세션이 바로 시작된다.
- 창구 칸에는 개인 기록 꼬리표, 공식전 칸에는 출전 도장.
- 미개설 창구(작명소·우리 동네)는 점선 도장으로 남겨 기대감만 만든다.
- 제목 아래에 레벨 칩과 계정 상태 한 줄.
- 기록판(랭킹) 페이지는 아직 없다. 순위는 결과 화면의 전국 상위 %와 판 백분위로만 보여준다.

### 1-2. 결과 → 공유
- **이미지 카드 공유** (구현 완료): "접수증" 콘셉트 — 창구에서 뽑아준 영수증 한 장. 절취 지그재그, 항목 열거, 등급 도장, 바코드, 관인. 1080×1350 PNG를 Canvas 2D로 그린다. 시안: `design/share3-s2-receipt.html`.
- **텍스트 공유** (계획, 미구현): Wordle식 이모지 그리드. SNS 텍스트 포스팅용.
- 화면 내 그리드/판정 표시는 이모지가 아닌 **그래픽(SVG)**으로 렌더한다. 이모지는 클립보드 텍스트 포맷에만 사용 (OS별 렌더 차이·촌스러움 방지).

### 1-3. 기록을 겨룬다
공유가 "밖으로" 퍼뜨리는 장치라면, 기록판은 "안에서" 돌아오게 만드는 장치다. §3 참조.

## 2. 계정 설계: 게스트 우선, 로그인은 보상형

### 2-1. 원칙
1. **로그인 없이 모든 게임 플레이 가능** (게스트). 로그인 요구는 첫 플레이 전이 아니라 **결과가 아까워진 순간**에 한다 — 데일리 게임의 생명은 진입장벽 0.
2. 게스트 상태: 스트릭·오늘의 결과·오답 기록은 localStorage. 기기를 바꾸면 사라짐을 UI에 명시.
3. **로그인하면 얻는 것** (로그인 유도 카피의 근거):
   - 기록 영구 저장 + 기기 간 동기화 (폰↔PC)
   - 전국 기록판/랭킹 등록 (닉네임)
   - 스트릭 보호 (localStorage 초기화에도 유지)
   - (2단계) 작명소 작품의 명예의 전당 귀속

### 2-2. 로그인 수단
| 수단 | 단계 | 비고 |
|---|---|---|
| **Google OAuth** | **구현 완료** | 코드 플로우를 라이브러리 없이 직접 구현. HMAC 서명 세션 쿠키 |
| **Kakao 로그인** | M3 | 한국 유저 커버리지 필수. 카톡 공유 연계 시너지 |
| Apple 로그인 | 앱 전환 시 | 웹 단계에서는 보류 |

- 구현: OAuth 인증 후 자체 세션(httpOnly 쿠키, 180일). 수집 정보는 **식별자·표시 이름**뿐이고 쿠키에는 개인정보를 싣지 않는다. 환경변수(GOOGLE_CLIENT_ID·GOOGLE_CLIENT_SECRET·AUTH_SECRET)가 하나라도 없으면 로그인 UI가 자동으로 숨고 비회원 모드만 동작한다.
- 게스트 → 로그인 전환 시 localStorage 기록을 서버와 **병합**한다(점수는 큰 값, 날짜는 최신). 서버·클라이언트가 같은 병합 규칙을 공유하므로 늦게 도착한 쓰기가 기록을 덮지 않는다. 로그인했다고 스트릭이 0이 되면 안 된다.

### 2-3. 로그인 유도 지점 (강요 금지)
1. 결과 화면: "기록판에 남기기" 버튼 → 미로그인 시 로그인 시트
2. 스트릭 7일 달성: "이 스트릭, 잃어버리면 아깝지 않나요?"
3. 새 기기 접속: "기존 기록 불러오기"

## 3. 기록 시스템 · 랭킹

### 3-1. 개인 기록 (로그인 시 서버 저장)
- **구현됨**: 감별사 레벨·누적 경험치, 모드별 무한 최고 연속과 평균 시간, 진짜 찾기 콤보(현재/최고), 공식전 연속 출전, 오늘의 공식전 결과. 모두 `user_state` 한 행에 묶여 기기 간 동기화된다.
- **미구현**: 마이페이지(월 캘린더 히트맵, 등급 변천사), 일별 결과 히스토리.

### 3-2. 전국 기록판 (일간 리더보드)
- **공식전은 점수 랭킹을 세우지 않는다.** 10점 만점 게임은 동점자가 수천 명이라 랭킹이 무의미하고 치팅 유인만 커진다. 비교축은 "전국 상위 %"와 등급 분포다(구현됨).
- **무한은 판 단위로 겨룬다.** 세션이 끝나면 최근 7일 다른 판들과 비교한 상위 %를 돌려준다(구현됨, 표본 20판부터). 이름 붙은 리더보드는 아직 없다.
- 리더보드 페이지를 만든다면 선행 조건이 있다. 지금은 클라이언트가 보낸 판 기록을 서버가 형식 검증만 하고 적재하므로, 공개 순위표를 세우기 전에 서버측 세션 검증이 필요하다.
- 닉네임 정책: 비속어·실명·지역비하 필터 (가짜 이름 블랙리스트 재사용). 신고 버튼.

### 3-3. 겨루기 확장 (M4 이후 후보, 확정 아님)
- 친구 대결: 내 결과 링크로 "같은 문제 도전" (데일리 특성상 같은 문제이므로 구현 비용 낮음)
- 그룹 리그: 회사/동네 단위 평균 경쟁 (맘카페·직장인 커뮤니티 확산 연계)

### 3-4. 치팅 정책
- 본편: 랭킹이 없으므로 방어 최소화 유지 ([04. 기술 사양](04-tech-spec.md) 정답 비전송 설계).
- 기록형 리더보드: 서버 판정 필수(클라이언트가 기록을 제출하는 게 아니라 서버가 라운드별 응답을 판정·집계). 비정상 속도(문항당 300ms 미만 연속 등) 기록은 랭킹 제외 큐로.

## 4. 데이터 모델 확장 ([04. 기술 사양](04-tech-spec.md)의 스키마에 추가)

실제 스키마는 [04. 기술 사양](04-tech-spec.md)에 있다. 요약하면 계정은 두 테이블로 끝난다.

```
app_user    ( 사용자 식별자, 표시 이름, 생성 시각 )
user_state  ( 사용자 식별자, 기록 전체를 담은 JSON, 갱신 시각 )
```
- 기록을 컬럼으로 쪼개지 않고 JSON 한 덩어리로 둔 이유: 게임이 늘 때마다 마이그레이션하지 않기 위해서다. 병합 규칙이 코드에 있으므로 스키마가 얇아도 된다.
- 게스트는 여전히 무계정이고, 익명 집계(question_stats·score_dist·endless_runs)는 계정과 무관하게 쌓인다.

## 5. 단계별 반영

| 단계 | 범위 |
|---|---|
| M1 (완료) | 홈=접수 대장, 게임 3종, 접수증 이미지 공유, **Google 로그인과 비회원 모드, 기록 클라우드 동기화**(초안의 M2 범위가 앞당겨짐) |
| M2 | 리더보드를 세운다면 서버측 세션 검증 먼저. 마이페이지(히트맵·등급 변천사) |
| M3 | Kakao 로그인, 기록형 리더보드 |
| M4 | 친구 대결·그룹 리그 검토 |

> 시안 데모 주석: 초기 아티팩트 시안의 "접수 대장"은 외부 로그인과 공유 DB로 이 플로우를 시뮬레이션한 것이다. 프로덕션은 본 문서의 Google OAuth 설계를 따른다(구현 완료).
