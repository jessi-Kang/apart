# 07. 서비스 플로우 · 계정 · 기록 시스템

시안 작업 중 확정된 방향을 기획으로 정리한다. 핵심 플로우는 **"게임을 고르고 → 플레이하고 → 결과를 공유하고 → 기록을 겨룬다"**의 4단계다.

## 1. 전체 서비스 플로우

```
[홈: 게임 선택] → [플레이] → [결과] → [공유(이미지 카드/텍스트)] → [기록판(랭킹)]
      ↑                                                                  │
      └────────────────── 내일 또 하기 (스트릭) ←─────────────────────────┘
```

### 1-1. 홈 = 게임 선택 화면
첫 화면은 인트로가 아니라 **게임 리스트**다 (시안 C 확정판 구조).
- 최상단: 본편 **감별 O/X** (하루 1회, 가장 크게 강조)
- 그 아래: 보너스/상시 모드 카드 (이름 조립, 진짜 찾기, 이후 높거나 낮거나)
- 잠금 카드: 미출시 모드(작명소, 우리 동네)를 노출해 기대감 형성
- 하단: **전국 기록판** (오늘의 기록 미리보기, 로그인 유도 접점)
- 본편 미완료 상태에서는 본편 카드에 "오늘 미접수" 표시로 데일리 습관을 우선 유도

### 1-2. 결과 → 공유
- **텍스트 공유** (클립보드): Wordle식 이모지 그리드. SNS 텍스트 포스팅용으로 유지.
- **이미지 카드 공유** (신규 확정): "창문 점등" 콘셉트 — 아파트 캐릭터의 창문 10개가 그날의 정답 그리드가 되어, 정답 수만큼 불이 켜진다. 정방형(1080×1080, 피드/카톡)과 세로형(1080×1920, 스토리/릴스) 2종. 시안: `design/sharecard-a.html`, `design/sharecard-c.html`.
- 화면 내 그리드/판정 표시는 이모지가 아닌 **그래픽(SVG)**으로 렌더한다. 이모지는 클립보드 텍스트 포맷에만 사용 (OS별 렌더 차이·촌스러움 방지).

### 1-3. 기록을 겨룬다
공유가 "밖으로" 퍼뜨리는 장치라면, 기록판은 "안에서" 돌아오게 만드는 장치다. §3 참조.

## 2. 계정 설계: 게스트 우선, 로그인은 보상형

### 2-1. 원칙
1. **로그인 없이 모든 게임 플레이 가능** (게스트). 로그인 요구는 첫 플레이 전이 아니라 **결과가 아까워진 순간**에 한다 — 데일리 게임의 생명은 진입장벽 0.
2. 게스트 상태: 스트릭·오늘의 결과·오답 기록은 localStorage. 기기를 바꾸면 사라짐을 UI에 명시.
3. **로그인하면 얻는 것** (로그인 유도 카피의 근거):
   - 기록 영구 저장 + 기기 간 동기화 (폰↔PC)
   - 전국 기록판/랭킹 등록 (닉네임)
   - 스트릭 보호 (localStorage 초기화에도 유지)
   - (2단계) 작명소 작품의 명예의 전당 귀속

### 2-2. 로그인 수단
| 수단 | 단계 | 비고 |
|---|---|---|
| **Google OAuth** | M2 | 1순위. 웹 기반 서비스라 가장 마찰 적음 |
| **Kakao 로그인** | M3 | 한국 유저 커버리지 필수. 카톡 공유 연계 시너지 |
| Apple 로그인 | 앱 전환 시 | 웹 단계에서는 보류 |

- 구현: OAuth 인증 후 자체 세션(httpOnly 쿠키). 수집 정보는 **식별자·이메일만** (이메일은 계정 복구용). 닉네임은 별도 입력, 실명·프로필 사진 미사용 → 개인정보 최소화.
- 게스트 → 로그인 전환 시 localStorage 기록(스트릭, 히스토리)을 서버로 **병합 마이그레이션**한다. 로그인했다고 스트릭이 0이 되면 안 된다.

### 2-3. 로그인 유도 지점 (강요 금지)
1. 결과 화면: "기록판에 남기기" 버튼 → 미로그인 시 로그인 시트
2. 스트릭 7일 달성: "이 스트릭, 잃어버리면 아깝지 않나요?"
3. 새 기기 접속: "기존 기록 불러오기"

## 3. 기록 시스템 · 랭킹

### 3-1. 개인 기록 (로그인 시 서버 저장)
- 일별 결과(점수·그리드·등급), 스트릭(현재/최장), 모드별 최고 기록(조립 성공률, 진짜 찾기 최대 콤보, 서바이벌 최고 기록), 누적 통계(평균 점수, 총 플레이 일수)
- 마이페이지: 월 캘린더 히트맵(점수별 색), 등급 변천사

### 3-2. 전국 기록판 (일간 리더보드)
- **본편은 점수 랭킹을 세우지 않는다.** 10점 만점 게임은 동점자가 수천 명이라 랭킹이 무의미하고, 치팅 유인만 커짐. 본편의 비교축은 "전국 평균 대비 상위 %"와 등급 분포.
- 랭킹을 세우는 곳: **기록 경쟁형 모드** — 진짜 찾기 연속 콤보, 높거나 낮거나 서바이벌 기록, (2단계) 우리 동네 지역별 평균. 기록형 지표는 동점이 드물어 리더보드가 성립한다.
- 표시 단위: 일간 TOP 10 + 내 순위/상위 %. 주간·월간은 지표 검증 후.
- 닉네임 정책: 비속어·실명·지역비하 필터 (가짜 이름 블랙리스트 재사용). 신고 버튼.

### 3-3. 겨루기 확장 (M4 이후 후보, 확정 아님)
- 친구 대결: 내 결과 링크로 "같은 문제 도전" (데일리 특성상 같은 문제이므로 구현 비용 낮음)
- 그룹 리그: 회사/동네 단위 평균 경쟁 (맘카페·직장인 커뮤니티 확산 연계)

### 3-4. 치팅 정책
- 본편: 랭킹이 없으므로 방어 최소화 유지 ([04. 기술 사양](04-tech-spec.md) 정답 비전송 설계).
- 기록형 리더보드: 서버 판정 필수(클라이언트가 기록을 제출하는 게 아니라 서버가 라운드별 응답을 판정·집계). 비정상 속도(문항당 300ms 미만 연속 등) 기록은 랭킹 제외 큐로.

## 4. 데이터 모델 확장 ([04. 기술 사양](04-tech-spec.md)의 스키마에 추가)

```sql
users        ( id PK, provider, provider_id, email, nickname, created_at )
user_daily   ( user_id, date PK, score, grid, grade )
user_stats   ( user_id PK, streak, max_streak, best_combo, best_survival, days_played )
leaderboard  ( date, mode, user_id PK, value )   -- 기록형 모드만
```
- 게스트는 여전히 무계정: `quiz_results`(익명 집계)는 그대로 유지. users 계열 테이블은 로그인 유저만.

## 5. 단계별 반영

| 단계 | 범위 |
|---|---|
| M1 (MVP) | 게스트만. 홈=게임 선택 구조로 시작(본편 카드 1개 + 잠금 카드). 이미지 공유 카드 포함 |
| M2 | Google 로그인, 개인 기록 저장·동기화, 전국 기록판(등급 분포·상위 %) |
| M3 | Kakao 로그인, 기록형 모드 리더보드(콤보·서바이벌), 마이페이지 히트맵 |
| M4 | 친구 대결·그룹 리그 검토 |

> 시안 데모 주석: 아티팩트 시안(`design/sian-c-gameshow.html`)의 "전국 기록판"은 claude.ai 로그인 + 공유 DB로 이 플로우를 시뮬레이션한 것이다. 프로덕션은 본 문서의 Google/Kakao OAuth 설계를 따른다.
