# 05. 확산·운영·지표

## 1. 바이럴 루트

확산 가설: **릴스 한 컷 + 댓글 싸움 + 데일리 인증 습관**의 3단 결합.

### 1-1. 릴스/쇼츠 (점화)
- 포맷: 화면에 단지명 하나 + "이거 진짜일까요?" 한 문장 → 3초 뒤 정답. 한 컷으로 끝나는 초저비용 템플릿.
- 소재는 그날 문제에서 가장 정답률 낮은 것 재활용 — 콘텐츠 제작이 아니라 출제 데이터 재활용이라 운영 비용 0에 수렴.
- 댓글 유도 문구를 정답 공개 전에 고정: "정답은 댓글 확인" → 댓글에서 "우리 동네 있는데요?" 싸움이 알고리즘 연료가 됨.
- 계정 운영: 릴스(인스타)·쇼츠(유튜브)·틱톡 동시 업로드, 주 3~5회.

### 1-2. 스레드/X 인증 문화 (습관화)
- 이모지 그리드 텍스트 공유가 이 루트의 엔진. Wordle 문법이라 보는 사람이 즉시 이해.
- 초기 시딩: 운영진이 매일 자기 점수 인증 + 부동산 밈 계정 몇 곳에 선공유 협업.

### 1-3. 커뮤니티 시딩 순서
1. **부동산 카페/커뮤니티** (부동산스터디 등): 1차 타깃이 밀집. "만점 나올 때까지 함" 류의 도전 포스트.
2. **직장인 커뮤니티** (블라인드 등): 점심시간 킬링 게임 포지션.
3. **지역 커뮤니티** (당근 동네생활, 맘카페): 2단계 우리 동네 모드 출시와 함께. "OO구 사람이면 8개는 맞혀야 함" 포맷.
- 시딩 메시지는 광고 티가 나면 죽는다 — 점수 인증 형태의 자연 포스트만.

### 1-4. 언론/뉴스레터 (보너스)
아파트 작명 문화 자체가 기사 소재 (실제로 반복 보도되는 주제). "AI도 못 따라가는 아파트 작명" 앵글로 부동산 뉴스레터·IT 매체에 제보. 기대하되 의존하지 않는다.

## 2. KPI

| 지표 | 정의 | MVP 성공 기준 (출시 4주차) |
|---|---|---|
| 완주율 | 시작 대비 10문제 완료 | 80% 이상 (2지선다 데일리에서 이걸 못 넘기면 게임 자체 문제) |
| 공유율 | 완주 대비 공유 버튼 클릭 | 15% 이상 |
| D1 리텐션 | 첫 플레이 다음날 재방문 | 30% 이상 |
| D7 리텐션 | 7일 후 재방문 | 15% 이상 |
| 유입 구성 | UTM 기준 채널별 비중 | 공유 링크 유입 40% 이상 (바이럴 루프 작동 증거) |
| DAU | — | 절대치 목표는 두지 않음. 리텐션·공유율이 좋으면 규모는 시딩으로 만들 수 있음 |

- **북극성 지표: D7 리텐션.** 데일리 게임은 습관 형성이 전부다. D7 15% 미달이면 채널 확장 대신 게임 루프(난이도·등급·복기)를 고친다.
- 보조 진단 지표: 평균 점수(6~7점대 유지가 이상적 — 너무 쉬우면 자랑할 게 없고 너무 어려우면 불쾌), 문제별 정답률 분포(가짜 프로파일 역측정, [03 문서](03-content-pipeline.md#2-2-프롬프트-설계-원칙-게임의-핵심-자산) 연동).

## 3. 운영 프로세스

> 운영 리드: Jessi. 아래 루틴은 초기 제안이며 운영하며 개정.

### 3-1. 주간 루틴
| 주기 | 작업 | 소요 (목표) |
|---|---|---|
| 주 1회 | 가짜 이름 검수 큐 처리 (150~200건) | 30분 |
| 주 1회 | 다음 주 7일치 편성 확정 (자동 초안 검토·교체) | 30분 |
| 주 3~5회 | 릴스/쇼츠 업로드 (템플릿화) | 회당 10분 |
| 월 1회 | K-apt 재수집 결과 반영 확인 | 30분 |
| 분기 1회 | LLM 배치 생성 + 프롬프트 개선 (정답률 역측정 반영) | 반나절 |

### 3-2. 검수 SLA
- 예비 편성분(폴백 2주치 포함)을 항상 유지 — 검수가 한 주 밀려도 서비스 무중단.
- 신규 블랙리스트 단어 발견 시: 기출제 풀 전체 재스캔 → 해당 건 즉시 회수.

### 3-3. 커뮤니티 대응 — "우리 동네 있는데요?" 플로우
정답 오류 제보는 최다 예상 CS이자 **가장 좋은 참여 신호**다 (틀렸다고 화내는 유저 = 몰입한 유저).
1. 결과 화면·정답 화면에 "정답 오류 제보" 버튼 (문제 자동 첨부, 자유 텍스트 1줄).
2. 운영자가 확인: 실제 오류(명칭 변경 미반영 등)면 → 다음날 랜딩 정정 공지 + 해당 문제 집계 제외 + 데이터 수정. 오류 아니면(재건축 전 옛 이름 기억 등) → 무대응 또는 FAQ 링크.
3. 당일 소급 수정은 하지 않는다 (이미 플레이한 유저와의 형평).
4. 정정 공지는 부끄러운 게 아니라 콘텐츠다 — "어제 7번, 사실 작년에 이름이 바뀌었습니다"는 그 자체로 공유 소재.

## 4. 리스크 및 대응

| 리스크 | 평가 | 대응 |
|---|---|---|
| **브랜드명 사용 (상표)** | 낮음 — 실존 단지명 언급은 사실의 적시이고, 출처는 공공데이터 | **로고·BI·서체·조감도 등 브랜드 자산은 절대 미사용** (텍스트만). 브랜드를 비하하는 연출 금지. 특정 브랜드 집중 출제로 표적처럼 보이지 않게 편성에서 브랜드 분산. 건설사 항의 접수 시 해당 브랜드 출제 일시 중단 후 검토하는 프로토콜 문서화 |
| **지역 비하 논란** | 중간 — 가짜 이름이 특정 지역 조롱으로 읽히면 서비스 전체가 위험 | 3중 방어: ① 생성 프롬프트 금지 지시 ② 자동 블랙리스트 필터 ③ 사람 검수 체크리스트 ([03 문서](03-content-pipeline.md#4-검수-프로세스-사람)). 임대·공공 단지 놀림 소재화 금지(출제 제외 태깅). 등급명·카피에서도 지역/계층 비하 톤 금지 |
| **데이터 오류 (개명·재건축)** | 중간 — 최다 CS 예상 | 월 1회 재수집, 어려움 난이도 실단지는 편성 시 수동 확인, 제보 플로우(§3-3) |
| **카피캣** | 높음 (성공 시 확실히 등장) | 구조적 방어([01 문서](01-service-overview.md#5-참고-사례와-차별점)): 콘텐츠 운영 해자 + 선점. 대응 원칙: 법적 다툼보다 운영 속도로 이김. 상표 출원(서비스명)은 트랙션 확인 즉시 진행 |
| **치팅 (만점 조작)** | 낮음 — 순위 경쟁 없는 게임 | 정답 비전송 설계([04 문서](04-tech-spec.md#3-api-설계))로 캐주얼 치팅만 방지, 그 이상 비용 안 씀 |
| **소재 고갈** | 낮음 — 실단지 수만 개 + 가짜는 무한 생성 | 90일 재출제 금지 기준으로도 풀은 수년치. 오히려 리스크는 고갈이 아니라 **품질 하락** → 정답률 역측정 루프로 방어 |
| **반짝 유행 후 소멸** | 근본 리스크 | D7 리텐션을 북극성으로 두고, 유행 파도가 오기 전에 습관 루프(스트릭·복기·주간 리캡)를 완성해 둔다. 2단계 모드는 유행 정점에서 소진이 아니라 하락 구간의 재점화 카드로 아껴 씀 |

## 5. 로드맵

### M1 — MVP (목표: 6주)
- 범위: 데일리 퀴즈 코어 루프, 등급/공유 카드(텍스트+OG), 스트릭, 전국 정답률, 오답 복기, 관리 화면(검수 큐·편성), K-apt 수집 파이프라인, 가짜 이름 1차 배치(검수 완료 500개+), 폴백 2주치.
- **완료 조건**: 지인 30명 클로즈드 테스트에서 완주율 80%+, "내일 또 할래?"에 60%+ 긍정. 미달 시 공개 론칭 연기하고 루프 수정.

### M2 — 공개 론칭 + 성장 (M1 후 2~4주)
- 범위: 커뮤니티 시딩(§1-3 순서), 릴스 운영 개시, 오류 제보 플로우 가동, 주간 리캡.
- **완료 조건**: 4주차 KPI 기준(§2) 달성 여부로 M3 진행 판단. D7 미달 시 M3 보류하고 코어 루프 개선.

### M3 — 서브 모드 (M2 검증 후 6~8주)
- 범위: 작명소 모드(조립·투표·명예의 전당), 우리 동네 모드(시/군/구 출제·지역 랭킹), 우승작의 데일리 편입 파이프라인.
- **완료 조건**: 작명소 참여율(DAU 대비 제출 5%+), 우리 동네 모드발 신규 유입 확인.

### M4 — 지역 확장·수익화 검토 (M3 이후)
- 지역 랭킹 고도화, 테마 주간, 상표 출원 마무리, 트래픽 수익화(제휴·광고) 실험. 이 단계는 M2~M3 데이터를 보고 별도 기획.
