# 03. 데이터·콘텐츠 파이프라인

게임의 재미는 전적으로 **"진짜 같은 가짜"와 "가짜 같은 진짜"의 품질**에서 나온다. 이 문서는 그 품질을 만드는 파이프라인을 정의한다. 리소스 배분 원칙: 프롬프트 튜닝·검수 룰에 가장 많은 시간을 쓴다.

현재 구현 상태 요약 (코드 기준):

| 단계 | 현재 | 위치 |
|---|---|---|
| 실단지 수집 | **매일 02:00(KST) 자동** (GitHub Actions) | `web/scripts/collect-kapt.mjs`, `.github/workflows/collect-kapt.yml` |
| 실단지 풀 | **정적 JSON 약 15,900건**(매일 는다) (DB 테이블 아님) | `web/data/apartments.json` |
| 승격 | 수집본 → 출제 풀, 더하기 방식 + 겹치는 가짜 솎기 | `web/scripts/promote-apartments.mjs` |
| 가짜 생성 | **규칙 생성기** (실단지 모양 학습) + 작명소(사람) | `web/scripts/generate-fakes.mjs`, `web/lib/naming.ts` |
| 가짜 풀 | **정적 JSON 2,000건** | `web/data/fake_names.json` |
| 자동 필터 | 실존 대조·형식·블랙리스트 + 말 거르기 + 겉모양 검사 | `validate-pool.mjs`, `lib/wordguard.ts`, `.claude/skills/qa` |
| 검수 | 작명소 접수 중 말 거르기에 걸린 것만 사람이 본다 | `/report` |
| 작명 출제 | **매일 05:10(KST) 자동** 내보내기·커밋·배포 | `.github/workflows/publish-coined.yml` |
| 출제 | 날짜 시드 결정적 생성 + 무한 모드 랜덤 소비 | `web/lib/daily.ts` 외 |

## 1. 실제 단지명 수집 (K-apt)

### 1-1. 소스 (구현)
- 공공데이터포털 **공동주택 단지 목록제공 V4**(`AptListService4/getSidoAptList4`) + **공동주택 기본 정보 V5**(`AptBasisInfoServiceV5/getAphusBassInfoV5`).
- 사용 필드: 단지명(`kaptName`), 주소(`as1/as2/as3` 또는 `kaptAddr`), 준공년도(`kaptUsedate` 앞 4자리), 세대수(`kaptdaCnt`).
- **수집 범위**: 시도 15곳, 총 약 15,900건. 목록에 있는데 받지 못한 것은 기본정보 API에 자료가 없거나 세대수·준공년도가 빈 단지라, 받을 수 있는 것은 다 받은 상태다.
  인자로 시도코드를 주면 그 시도를 받고, 다시 실행하면 기존 수집본에 이어붙는다.
  **시도코드에 함정이 있다**: 강원은 42가 아니라 51, 전북은 45가 아니라 52다(특별자치도 전환).
  확인된 코드 표는 `collect-kapt.mjs` 주석에 있다.
- **기본정보 V5 일일 쿼터가 5,000건**이라 하루에 다 받을 수 없다. 야간 작업은 `LIMIT=4000`으로 돌고, 담당 구역은 시·도 단위만 둔다(구 단위는 창구마다 적용 범위가 갈려서 두지 않는다).
- **쿼터를 아끼는 장치**: 받아 보고 버린 단지(결측·정보 없음)는 수집본의 `skipped`에 날짜와 함께 적어 두고 90일 동안 다시 받지 않는다. 적어 두지 않으면 같은 단지를 매일 다시 호출하게 된다.
- **빈 목록은 실패다**: 포털이 가끔 200에 빈 목록을 돌려준다. 0건이면 예외로 보고 20초·40초 뒤 두 번 더 시도하며, 한 시도가 안 되면 그 시도만 건너뛰고 보고에 남긴다. 한 쪽은 300건씩 받는다(1,000건은 응답이 느려 끊길 여지가 크다).
- 광주(29)와 전남(46)은 목록 API가 계속 빈 응답이라 아직 없다.
- **야간 작업** (`.github/workflows/collect-kapt.yml`, 02:00 KST): 수집 → 승격 → 가짜 채우기 → `validate-pool` → `check-wordguard` → 바뀐 것이 있으면 커밋과 배포 훅 → 결과를 이슈 `야간 작업 일지`에 댓글로 남긴다. 성공이든 실패든 남기고, 못 받은 시도는 제목 바로 밑에 올린다. 시크릿 `KAPT_API_KEY`가 없으면 첫 단계에서 건너뛴다.
- 손으로 돌릴 때: `cd web && npm run collect-kapt` (인증키는 `web/.env.local`의 `KAPT_API_KEY`, 커밋 금지).

### 1-2. 정제 규칙 (수집 → 출제 풀)

수집 스크립트가 이미 적용하는 것:
1. 괄호 병기 제거·공백 정규화("래미안OO(1단지)" → "래미안OO").
2. 차수 중복 제거: 공백을 지운 `familyKey`("래미안OO 1차" → "래미안oo")로 대표 1건만 남긴다.
3. 20자 초과 단지명 제외 (카드 UI가 깨지고 검증기 형식 규칙에도 걸린다).
4. 세대수·준공년도 결측 단지 제외 (정답 공개 화면을 채울 수 없다).
5. 규칙 기반 난이도 초기 라벨 (§3).

출제 직전에 `lib/data.ts`가 한 번 더 거르는 것 — **관리 단위 행**:
K-apt 원본에는 단지명이 아니라 관리 단위가 이름 칸에 들어온 행이 섞여 있다.
`대림아파트201동`, `OO제2관리사무소`, `수유벽산201아파트`, `텐즈힐2구역`, `OO임대` 같은 것들이다.
문제로 내면 "이게 아파트 이름이야?" 소리가 나오고, `임대`·`제N`은 같은 단지가 두 번 나오는 중복이기도 하다.
정규식 하나(`ADMIN_NOISE`)로 5,469건 중 200여 건을 빼고 낸다.
`validate-pool`도 같은 규칙으로 몇 건이 빠지는지 경고로 알린다 (두 곳의 정규식은 같이 고친다).

아직 없는 것:
- **출제 제외 태깅**(`excluded` 플래그): 미구현. 민감 단지 제외는 지금은 수집본 검토 단계에서 사람이 행을 지우는 방식뿐이다. 리스크 정책은 [05 문서](05-growth-and-ops.md#4-리스크-및-대응) 연동.
- **상시 대조 인덱스 파일**: 별도로 만들지 않는다. `validate-pool`이 실행할 때마다 실단지명 집합을 메모리에 만들어 대조한다.

### 1-3. 결과물과 승격 절차 (구현)
- 수집 결과는 `web/data/apartments.collected.json`에 쓰고 `promote-apartments.mjs`가 `apartments.json`으로 승격한다. **승격은 덮어쓰기가 아니라 더하기다** — 출제 풀에는 수집본에 없는 단지가 손으로 들어가 있어, 복사로 만들면 매일 밤 사라진다. 같은 단계에서 새 실단지와 사실상 같아진 가짜를 솎는다(실단지는 사실이고 가짜는 지어낸 것이라 물러나는 쪽은 가짜다).
- 현재 풀: **약 15,900건, 시도 15곳**(2026-10 기준, 매일 밤 새 단지가 더해진다). 서울 2,889 · 경기 2,801 · 부산 1,361 · 경남 1,287 · 대구 1,061 · 인천 1,004 · 경북 981 · 충남 920 · 전북 796 · 강원 739 · 충북 721 · 대전 509 · 울산 458 · 제주 172 · 세종 139. 항목 필드는 `id`(`k` + kaptCode) / `name` / `sido` / `sigungu` / `dong` / `builtYear` / `households` / `difficulty`.
- 정답 공개 화면의 "서울특별시 서초구 반포동 · 2023년 · 2,990세대"가 이 데이터에서 나온다. 표기 규칙: 시/도 + 시/군/구 + 동까지만(도로명 상세주소 미노출), 준공년도 4자리, 세대수 콤마 표기.

## 2. 가짜 단지명 생성

### 2-1. 세 갈래
- 현재 풀 **2,000건** = 초기 생성분 499(`f…`) + 생성기 1,496(`g…`) + 작명소 5(`c…`, `coined: true`). 필드는 `id` / `name` / `hint` / `difficulty`(+ `coined`).
- **생성기**(`npm run generate-fakes`): 모델 호출 없이 규칙으로 짓는다. 야간 작업이 수집·승격 다음 자리에서 돌려 하루 최대 120건, 풀이 2,000건이면 멈춘다. 실단지가 늘어 가짜가 솎이면 그만큼 채운다.
- **작명소**(`/n`): 사람이 짓는다. 말 거르기를 거쳐 자동 승인되면 05:10 야간 작업이 출제 풀로 내보낸다(§4).
- 셋 다 같은 관문(`validate-pool`·`check-wordguard`)을 지난다. **런타임 모델 호출 0.**

### 2-2. 생성기 설계 (게임의 핵심 자산)

틀을 손으로 적지 않는다. 손으로 정한 틀은 겉모양에 티가 난다 — 초기 생성분은 띄어쓴 이름이 49.6%였는데 실단지는 15.9%라, 공백만 세도 가짜를 76% 맞힐 수 있었다. 그래서 실단지를 어휘 사전으로 토막 내 **어떤 배열이 얼마나 흔한지, 그 배열이 띄어 쓰이는 비율, 글자 수 분포**를 배우고 그 분포대로 짓는다.

- **어휘**는 `web/data/name_pieces.json` 한 곳에 있고 작명소(`lib/naming.ts`)와 생성기가 같이 본다. 두 곳에 적으면 갈라진다. 지역어는 적지 않고 실단지의 동 이름을 그대로 쓴다(없는 동네 이름은 그 지역 사람이 바로 알아본다). 동 이름으로 안 잡히는 시·군·생활권 이름은 `areaExtra`에 둔다.
- **길이를 먼저 정한다.** 실단지 길이 분포에서 목표 글자 수를 뽑고 그 길이가 나오는 틀 중에서 고른다. 마구 뽑아 버리는 방식은 많은 것을 줄일 뿐 없는 것을 만들지 못해서, 11자 이상이 실단지에서 18.7%인데 0%로 나왔다. 길이를 먼저 정하는 쪽이 200건에 1,200번 시도로 끝난다(버리는 방식은 45만 번).
- **이음매는 실단지에 묻는다.** 동네 이름이 한쪽에만 낀 이음매만 자유고, 나머지는 실단지에서 실제로 붙어 본 적 있는 짝이어야 한다. "쌍용래미안"(남의 회사 둘)·"마을타운"(같은 뜻 두 번)을 규칙으로 막으면 "현대힐스테이트"처럼 실제로 있는 이름까지 막힌다. 동네 이름은 이름당 하나다.
- **맨 앞·맨 뒤 자리**는 실단지에서 그 자리에 와 본 낱말만 쓰고, 끝 낱말은 실단지가 그 낱말로 끝나는 횟수를 무게로 고른다("…아파트"가 36.3%).
- 난이도는 실단지와 같은 규칙으로 매긴다(§3). 다른 자로 재면 난이도 칸마다 한쪽 출처만 쌓인다.
- `hint`는 "실단지에 없는 조합입니다" 하나다. 어떤 틀로 지었는지 알려 주면 틀을 외워서 맞힌다.
- 지역 특화 가짜는 별도 필드 없이 이름 안의 지역 토큰으로 실행 시점에 판별한다(`lib/data.ts`). 구역을 골라 노는 동안 가짜만 딴 동네 이름을 달고 나오면 공짜 힌트가 된다.

### 2-2-1. 겉모양 검사 (`/qa` 데이터 항목)
문제는 진짜:가짜가 반반이므로, 어떤 특징을 가진 이름을 무조건 가짜라고 찍었을 때의 적중률은 가짜비율 ÷ (가짜비율 + 실단지비율)이다. 띄어쓰기·6자 이하·11자 이상·끝 낱말(아파트·마을·타운·맨션) 어느 것이든 **65%를 넘으면 실패**다. 눈으로 몇십 건 훑어서는 안 보이던 쏠림이 이 검사로 잡힌다.

### 2-3. 자동 필터 (`npm run validate-pool`, 구현)
모든 가짜 × 모든 실단지를 대조한다. 하나라도 걸리면 exit 1.
1. **실존 일치 제거**: 공백 제거·소문자화 후 완전 일치.
2. **유사 일치 제거**: 편집거리(Levenshtein) ≤ 2 또는 토큰 일치율 ≥ 80%. "사실상 실존"인 가짜가 정답 시비를 만들기 때문. 편집거리 3~4는 실패가 아니라 **경고**로 출력한다.
3. **블랙리스트**: 지역 비하·비속어 계열. 코드에는 최소 시드만 두고 운영하며 추가한다.
4. **형식 검증**: 길이 2~20자, id·이름 중복 없음, 필수 필드(`name`·`hint`) 존재, 실단지 메타(`sido`·`sigungu`·`builtYear`·`households`) 결측 없음.

브랜드 오탈자("래미앙" 등) 탐지는 아직 규칙이 없다. 생성 단계 지시와 사람 검토에 의존한다.

### 2-4. 힌트 문구
정답 공개 화면의 한 줄 힌트는 `hint` 필드에서 나온다. 초기 생성분은 트릭을 살짝 알려주는 문구("펫네임이 하나 더 얹혔습니다" 등), 생성기 분은 "실단지에 없는 조합입니다", 작명소 분은 "감별사가 작명소에서 직접 지은 이름입니다"다. 공식전·무한 판정 응답에 그대로 실린다.

### 2-5. 겉모양이 힌트가 되면 안 된다

길이·띄어쓰기·끝 낱말처럼 이름을 읽지 않아도 보이는 것이 한쪽으로 쏠리면 그것만으로 가짜를 가려낼 수 있다. 생성기는 실단지 분포를 따르고, 풀 전체는 §2-2-1 검사가 지킨다. 실단지가 늘수록 4~6자 조합은 대부분 실존이라 짧은 가짜 만들기가 어려워지는데, 그때는 야간 보고의 "짧은 이름" 수치가 먼저 알려 준다.

## 3. 난이도 라벨링

| 난이도 | 진짜 문제 기준 | 가짜 문제 기준 |
|---|---|---|
| 쉬움 | 전국구 유명 단지, 단순 작명("OO주공1단지", "래미안OO") | 문법 파괴·과잉 조합으로 웃긴 이름 |
| 중간 | 브랜드+펫네임 1개의 평범한 신축 | 문법은 완벽하나 조합이 낯선 이름 |
| 어려움 | 펫네임 2개 이상의 실존 단지 ("이게 진짜라고?" 담당) | 실단지와 한 끗 차이 프로파일 |

- 실단지 라벨은 **수집 시 자동**: 펫네임 사전(포레·에듀·노블·퍼스티지 등 17개) 히트 수와 토큰 수로 판정한다. 펫네임 2개 이상 또는 토큰 4개 이상이면 `hard`, 펫네임 1개 또는 토큰 3개면 `mid`, 나머지는 `easy`.
- 생성기 분 가짜도 **같은 규칙**으로 매긴다. 글자 수로 따로 매겼을 때 생성분의 88%가 `hard`로 몰려 어려움 칸이 한쪽 출처로 들어찬 적이 있다. 초기 생성분과 작명소 분은 등록 때 정한 값이다.
- **실측 재라벨링은 미구현**: `question_stats`가 `(date, no)` 단위라 문항 id와 연결되지 않아, 정답률을 개별 단지·가짜 이름에 되먹일 경로가 아직 없다. 집계 스키마에 항목 참조를 추가하는 것이 선행 조건이다.

## 4. 검수 프로세스

> 운영 리드: Jessi. 사람이 보는 것은 작명소 접수 중 말 거르기에 걸린 것뿐이다.

### 4-1. 현재 방식 (작명소 접수)
- **말 거르기**(`lib/wordguard.ts`)가 세 갈래로 나눈다. 명백한 말(욕설·성적 표현·집단 비하)은 접수 자체를 막고, 조금이라도 걸리는 말은 사유를 달아 대기로 세우고, 아무 신호도 없으면 자동 승인한다.
- 운영 화면 `/report`에서 대기분을 승인·반려·되돌리기한다(운영자만). 반려는 지우지 않고 표시로 남긴다 — 같은 이름이 다시 오면 왜 뺐는지 알아야 한다.
- **승인과 출제는 다른 단계다.** 승인된 이름은 `publish-coined.yml`(05:10 KST)이 접수 12시간이 지난 것만, 한 번에 30건까지 `export-coined`로 내보내고 `validate-pool`·`check-wordguard`를 통과하면 커밋·배포한다. 12시간은 잘못 통과한 이름을 반려할 틈이다.
- 사전을 늘릴 때는 `npm run check-wordguard`를 돌린다. 실단지와 기존 가짜가 하나라도 걸리면 실패다 — "성당"(대구 성당동), "야동"(가야동), "시신"(정관신도시 신동)처럼 두 글자 낱말은 경계를 넘어 우연히 만들어진다.
- 사람이 볼 때의 체크리스트:
  1. 실존처럼 들리는가? (게임 품질)
  2. 지역·집단 비하로 읽힐 여지가 없는가? (안전)
  3. 특정 실존 단지를 연상시켜 그 단지에 대한 조롱이 되지 않는가? (안전)
  4. 오탈자·어색한 조합이 없는가? (품질)
- 수집본 쪽은 사람이 보지 않는다. 정제 규칙(§1-2)과 `validate-pool`이 대신하고, 야간 보고를 읽는 것으로 갈음한다.

### 4-2. 실단지 쪽 검수
가짜만 검수하는 게 아니다. 어려움 난이도로 나갈 실단지("이게 진짜라고?" 후보)는 명칭이 최신인지(개명·재건축), 메타데이터가 맞는지 승격 시 확인한다. "우리 동네 있는데요? 그거 이름 바뀌었는데요"가 최다 예상 클레임이기 때문.

## 5. 출제 운영

### 5-1. 현재 구조 (구현)
- **무한 모드가 본편**이다. 창구에 들어가면 곧바로 무한 판이 시작되고, 출제는 풀 전체에서 매 요청 랜덤으로 뽑는다(`web/lib/endless.ts`). 감별 O/X는 클라이언트가 최근 문제의 정체(r/f 여덟 자)를 보내고, 같은 쪽이 셋 이상 이어지면 서버가 반대쪽 확률을 80%로 올린다 — 독립 시행은 같은 쪽이 대여섯 번 이어지는 구간을 반드시 만드는데, 완전히 막으면 그것으로 다음 답을 맞히므로 누르기만 한다.
- **데일리는 "제N호 공식전"**으로, 게임 안 칩으로 선택 참가한다. 문제는 테이블에 저장하지 않고 **KST 날짜를 시드로 결정적으로 생성**한다(`web/lib/daily.ts`, 조립 `assemble.ts`, 진짜 찾기 `findreal.ts`는 시드 오프셋으로 분리). 전원 같은 문제를 보되 저장소는 필요 없다.
- 공식전 구성 규칙: 진짜:가짜 = 4:6~6:4 랜덤, 난이도 커브는 위치별 `easy, easy, mid×5, hard×3`. 해당 난이도 후보가 모자라면 인접 난이도로 대체한다.
- 조립 창구 정답 풀은 **토큰 2개 이상으로 쪼개지는 실단지 2,490건**, 함정 조각은 가짜 이름의 토큰 중 **2~6자**만 쓴다(붙여 쓴 긴 가짜가 통째로 조각 하나가 되면 칩이 격자를 밀어내고 길이만으로 함정인 것이 드러난다).

### 5-2. 미구현 (기획 유지)
- **90일 재출제 금지**: `last_used_at` 같은 출제 이력이 없어 적용되지 않는다. `daily.ts`에 TODO로 남아 있다.
- **주간 편성 도구**: 7일치를 미리 편성하고 운영자가 교체하는 흐름. 날짜 시드 방식이 그 자리를 대신하고 있어 우선순위가 낮다.
- **편성 감각 규칙**: 하루 10문제에 "웃긴 가짜" 1개 + "이게 진짜라고?" 실단지 1개를 반드시 넣는 규칙. 지금은 난이도 커브만 있고 이 보장은 없다.
- **폴백 세트**: 편성 사고용 예비 문제 세트. 시드 생성 방식에서는 데이터 파일만 있으면 문제가 비지 않으므로 필요성이 낮아졌다.
- **오류 제보 처리**: 버그 제보 창구(`/bug`)는 있고 운영 화면에서 읽는다. 집계 제외 플래그는 아직 없다. 처리 플로우는 [05 문서](05-growth-and-ops.md#3-운영-프로세스) 참조.
