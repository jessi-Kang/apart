# 03. 데이터·콘텐츠 파이프라인

게임의 재미는 전적으로 **"진짜 같은 가짜"와 "가짜 같은 진짜"의 품질**에서 나온다. 이 문서는 그 품질을 만드는 파이프라인을 정의한다. 리소스 배분 원칙: 프롬프트 튜닝·검수 룰에 가장 많은 시간을 쓴다.

## 1. 실제 단지명 수집 (K-apt)

### 1-1. 소스
- **공공데이터포털 공동주택(K-apt) 단지 목록/기본정보 API** — 전국 공동주택 수만 개.
- 사용 필드: 단지명, 법정동 주소(시/도·시/군/구·읍/면/동), 준공년도(사용승인일), 세대수.
- 갱신 주기: **월 1회** 전체 재수집. 신축 입주·명칭 변경(재건축 후 개명 등) 반영. 수집 배치는 로컬/CI에서 실행 — 런타임 의존 없음.

### 1-2. 정제 규칙 (수집 → 출제 풀)
1. 중복 제거: 동일 단지의 차수 분리("O단지 1차/2차")는 대표 1건만.
2. 특수문자·공백 정규화, 괄호 병기 제거("래미안OO(1단지)" → "래미안OO").
3. **출제 제외 태깅** (풀에는 남기되 데일리 출제 안 함):
   - 임대·공공 단지명 중 놀림 소재화 우려가 있는 것 (리스크 정책, [05 문서](05-growth-and-ops.md#4-리스크-및-대응) 연동)
   - 이름에 개인명·종교명 등 민감 요소 포함 단지
4. **가짜 대조용 인덱스 생성**: 전체 실단지명의 정규화 문자열 집합 — 가짜 이름 검증(§2-3)과 작명소 모드 이스터에그 대조에 사용.

### 1-3. 메타데이터 활용
정답 공개 화면의 "서울 서초구 반포동 · 2023년 · 2,990세대"가 이 데이터에서 나온다. 표기 규칙: 시/군/구 + 동까지만 (도로명 상세주소 미노출), 준공년도 4자리, 세대수 콤마 표기.

## 2. 가짜 단지명 생성 (LLM 배치)

### 2-1. 구조 원칙
- **사전 배치 생성 + 캐싱**: 분기당 1~2회 수천 개 단위로 생성해 DB에 적재. **런타임 LLM 호출 0** — 서버비 거의 0의 핵심.
- 생성 단가가 낮으므로 과잉 생성 → 강하게 걸러내는 전략 (생성 3,000개 → 자동 필터 → 사람 검수 → 출제 풀 500~800개 목표, 통과율은 튜닝하며 조정).

### 2-2. 프롬프트 설계 원칙 (게임의 핵심 자산)
실제 한국 아파트 작명 문법을 분해해 프롬프트에 주입한다:

```
[브랜드] + [지역/입지 키워드] + [펫네임] (+ [차수/블록])
 래미안     리버/센트럴/역명      포레/에듀/노블/퍼스티지
```

- **Few-shot에 실단지명 포함**: K-apt에서 뽑은 실제 이름 20~30개를 예시로 주고 "이 문법을 따르되 실존하지 않는 이름"을 요구.
- **난이도별 생성 프로파일**:
  - 쉬움: 문법은 맞지만 조합이 과함 (펫네임 3개 연속 등) — 웃음 담당
  - 어려움: 실단지와 한 끗 차이 (실존 브랜드 + 그럴듯한 실존 지명 + 흔한 펫네임 1개) — 긴장 담당
- **지역 변주**: 우리 동네 모드용으로 특정 시/군/구의 실제 동명·랜드마크를 재료로 주입한 지역 특화 가짜 생성.
- **금지 지시**: 실존 지역 비하 뉘앙스, 저급 언어유희, 실존 단지명 그대로 재조합 금지를 프롬프트 단계에서 1차 차단 (최종 차단은 §3 검수).
- 프롬프트 버전을 관리하고, 각 가짜 이름에 `프롬프트 버전`·`생성 프로파일`을 기록 → 출시 후 **문제별 실제 정답률로 어떤 프로파일이 "잘 속이는지" 역측정**해 프롬프트를 개선하는 루프를 만든다.

### 2-3. 자동 필터 (생성 직후, 코드로)
1. **실존 일치 제거**: 정규화 후 실단지 인덱스와 완전 일치 제거.
2. **유사 일치 제거**: 실단지명과 편집거리(Levenshtein) ≤ 2 또는 토큰 일치율 80% 이상이면 제거 — "사실상 실존"인 가짜가 정답 시비를 만들기 때문.
3. **블랙리스트**: 비속어, 지역 비하 연상 표현(사투리 희화화, 특정 지역+부정어 조합 등), 실존 인물명. 블랙리스트는 운영하며 계속 추가.
4. **형식 검증**: 길이(4~20자), 허용 문자, 브랜드 오탈자("래미앙" 등) 제거 — 오탈자는 즉시 가짜 티가 나서 게임을 망침.

### 2-4. 생성 힌트 문구
정답 공개 화면의 "이건 AI가 지은 이름 🤖" 아래 한 줄 힌트를 생성 시 함께 만든다. 예: "실존 브랜드 + 있을 법하지만 없는 조합", "펫네임을 하나 더 얹었습니다". 힌트가 가짜의 '트릭'을 살짝 알려줘 학습 재미를 만든다.

## 3. 난이도 라벨링

| 난이도 | 진짜 문제 기준 | 가짜 문제 기준 |
|---|---|---|
| 쉬움 | 전국구 유명 단지, 단순 작명("OO주공1단지", "래미안OO") | 문법 파괴·과잉 조합으로 웃긴 이름 |
| 중간 | 브랜드+펫네임 1개의 평범한 신축 | 문법은 완벽하나 조합이 낯선 이름 |
| 어려움 | 펫네임 2개 이상의 실존 단지 ("이게 진짜라고?" 담당) | 실단지와 한 끗 차이 프로파일 |

- 초기 라벨은 규칙 기반(토큰 수, 펫네임 수, 브랜드 유무) + 검수자 수동 보정.
- 출시 후엔 **실측 정답률로 자동 재라벨링**: 정답률 75%↑ 쉬움 / 40~75% 중간 / 40%↓ 어려움. 데이터가 쌓일수록 난이도 커브가 정확해진다.

## 4. 검수 프로세스 (사람)

> 운영 설계 전제: 검수·운영 프로세스는 Jessi 리드. 아래는 초기 제안 룰이며 운영하며 개정한다.

### 4-1. 검수 큐
- 자동 필터를 통과한 가짜 이름이 검수 큐에 쌓임. 검수자는 관리 화면에서 건당 승인/반려/보류.
- 검수 관점 체크리스트:
  1. 실존처럼 들리는가? (게임 품질)
  2. 지역·집단 비하로 읽힐 여지가 없는가? (안전)
  3. 특정 실존 단지를 연상시켜 그 단지에 대한 조롱이 되지 않는가? (안전)
  4. 오탈자·어색한 조합이 없는가? (품질)
- 반려 시 반려 사유 태그 필수 → 사유 통계가 프롬프트 개선 입력이 됨.
- 처리량 가이드: 1건 10초 내외, 주 1회 30분 세션으로 150~200건 → 주간 편성에 충분.

### 4-2. 실단지 쪽 검수
가짜만 검수하는 게 아니다. 어려움 난이도로 편성될 실단지("이게 진짜라고?" 후보)는 명칭이 최신인지(개명·재건축), 메타데이터가 맞는지 편성 시 1회 확인. "우리 동네 있는데요? 그거 이름 바뀌었는데요"가 최다 예상 클레임이기 때문.

## 5. 일일 출제 운영

- **주 단위 편성**: 매주 1회, 7일치(70문제)를 미리 편성. 편성 도구가 규칙(비율 4:6~6:4 랜덤, 난이도 커브, 90일 재출제 금지)에 맞는 초안을 자동 생성 → 운영자가 검토·교체 후 확정.
- **편성 감각**: 하루 10문제 안에 "웃긴 가짜" 1개 + "이게 진짜라고?" 실단지 1개는 반드시 포함 — 이 두 개가 그날의 공유 소재.
- **폴백**: 편성 누락·데이터 사고 시 예비 문제 세트(검수 완료 2주치)로 자동 대체. 데일리 게임은 하루라도 구멍 나면 습관이 끊기므로 폴백은 필수.
- **오류 대응**: 출제 후 정답 오류 제보(실단지인데 가짜 처리 등) 접수 시 — 당일 수정은 하지 않고(이미 플레이한 유저와의 형평), 다음날 랜딩에 정정 공지 + 해당 문제는 집계 제외. 처리 플로우는 [05 문서](05-growth-and-ops.md#3-운영-프로세스) 참조.

## 6. 파이프라인 요약도

```
[K-apt API] ─월1회─> [수집·정제] ─> [실단지 풀 + 대조 인덱스]
                                          │
[LLM 배치 생성] ─> [자동 필터] ─> [검수 큐(사람)] ─> [가짜 풀]
                                          │
                              [주간 편성(자동 초안+운영 확정)]
                                          │
                                   [daily_quizzes]
                                          │
                              [출시 후 정답률 실측] ──> 난이도 재라벨 · 프롬프트 개선
```
