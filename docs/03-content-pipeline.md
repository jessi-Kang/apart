# 03. 데이터·콘텐츠 파이프라인

게임의 재미는 전적으로 **"진짜 같은 가짜"와 "가짜 같은 진짜"의 품질**에서 나온다. 이 문서는 그 품질을 만드는 파이프라인을 정의한다. 리소스 배분 원칙: 프롬프트 튜닝·검수 룰에 가장 많은 시간을 쓴다.

현재 구현 상태 요약 (코드 기준):

| 단계 | 현재 | 위치 |
|---|---|---|
| 실단지 수집 | 수동 실행 배치. 서울 한정 | `web/scripts/collect-kapt.mjs` |
| 실단지 풀 | **정적 JSON 2,889건** (DB 테이블 아님) | `web/data/apartments.json` |
| 가짜 생성 | LLM 배치(대화형) + 수기 등록 | — |
| 가짜 풀 | **정적 JSON 200건** | `web/data/fake_names.json` |
| 자동 필터 | 구현 (실존 대조·형식·블랙리스트) | `web/scripts/validate-pool.mjs` |
| 검수 큐·관리 화면 | **미구현** (수집본 파일 눈검사로 대체) | — |
| 출제 | 날짜 시드 결정적 생성 + 무한 모드 랜덤 소비 | `web/lib/daily.ts` 외 |

## 1. 실제 단지명 수집 (K-apt)

### 1-1. 소스 (구현)
- 공공데이터포털 **공동주택 단지 목록제공 V4**(`AptListService4/getSidoAptList4`) + **공동주택 기본 정보 V5**(`AptBasisInfoServiceV5/getAphusBassInfoV5`).
- 사용 필드: 단지명(`kaptName`), 주소(`as1/as2/as3` 또는 `kaptAddr`), 준공년도(`kaptUsedate` 앞 4자리), 세대수(`kaptdaCnt`).
- **수집 범위는 현재 서울특별시(시도코드 11) 한정.** 인자로 다른 시도코드를 주면 확장되지만 아직 수집하지 않았다.
- 실행: `cd web && npm run collect-kapt`. 인증키는 `web/.env.local`의 `KAPT_API_KEY`(커밋 금지). 기본정보 API 일일 쿼터(5,000건)를 보호하려고 `LIMIT`(기본 800) 상한을 두고, 다시 실행하면 기존 수집본에 이어붙는다.
- 갱신 주기: **월 1회 전체 재수집은 계획.** 현재는 필요할 때 사람이 돌리는 수동 배치이며, 자동 스케줄·CI 배치는 미구현.

### 1-2. 정제 규칙 (수집 → 출제 풀)

수집 스크립트가 이미 적용하는 것:
1. 괄호 병기 제거·공백 정규화("래미안OO(1단지)" → "래미안OO").
2. 차수 중복 제거: 공백을 지운 `familyKey`("래미안OO 1차" → "래미안oo")로 대표 1건만 남긴다.
3. 20자 초과 단지명 제외 (카드 UI가 깨지고 검증기 형식 규칙에도 걸린다).
4. 세대수·준공년도 결측 단지 제외 (정답 공개 화면을 채울 수 없다).
5. 규칙 기반 난이도 초기 라벨 (§3).

출제 직전에 `lib/data.ts`가 한 번 더 거르는 것 — **관리 단위 행**:
K-apt 원본에는 단지명이 아니라 관리 단위가 이름 칸에 들어온 행이 섞여 있다.
`대림아파트201동`, `OO제2관리사무소`, `수유벽산201아파트`, `텐즈힐2구역`, `OO임대` 같은 것들이다.
문제로 내면 "이게 아파트 이름이야?" 소리가 나오고, `임대`·`제N`은 같은 단지가 두 번 나오는 중복이기도 하다.
정규식 하나(`ADMIN_NOISE`)로 2,889건 중 124건을 빼고 2,765건으로 낸다.
`validate-pool`도 같은 규칙으로 몇 건이 빠지는지 경고로 알린다 (두 곳의 정규식은 같이 고친다).

아직 없는 것:
- **출제 제외 태깅**(`excluded` 플래그): 미구현. 민감 단지 제외는 지금은 수집본 검토 단계에서 사람이 행을 지우는 방식뿐이다. 리스크 정책은 [05 문서](05-growth-and-ops.md#4-리스크-및-대응) 연동.
- **상시 대조 인덱스 파일**: 별도로 만들지 않는다. `validate-pool`이 실행할 때마다 실단지명 집합을 메모리에 만들어 대조한다.

### 1-3. 결과물과 승격 절차 (구현)
- 수집 결과는 `web/data/apartments.collected.json`에 쓰고, **사람이 검토한 뒤** `apartments.json`으로 승격한다. 무검토로 출제 풀에 들어가지 않게 하는 2단계 구조.
- 현재 풀: **2,889건, 서울 25개 자치구 전역.** 항목 필드는 `id`(`k` + kaptCode) / `name` / `sido` / `sigungu` / `dong` / `builtYear` / `households` / `difficulty`.
- 정답 공개 화면의 "서울특별시 서초구 반포동 · 2023년 · 2,990세대"가 이 데이터에서 나온다. 표기 규칙: 시/도 + 시/군/구 + 동까지만(도로명 상세주소 미노출), 준공년도 4자리, 세대수 콤마 표기.

## 2. 가짜 단지명 생성 (LLM 배치)

### 2-1. 구조 원칙
- **사전 배치 생성 + 정적 파일 적재**: 대화형 LLM으로 수십 건씩 묶어 만들고, `validate-pool` 대조를 통과한 것만 `fake_names.json`에 등록한다. **런타임 LLM 호출 0** — 서버비 거의 0의 핵심.
- 현재 풀: **200건** (쉬움 54 / 중간 85 / 어려움 61). 필드는 `id` / `name` / `hint` / `difficulty` 네 개뿐이다.
- 계획: 생성 단가가 낮으므로 과잉 생성 → 강하게 걸러내는 전략(생성 수천 건 → 자동 필터 → 검수 → 풀 500~800건). 지금은 그 절반도 안 되는 규모이며, 무한 모드가 본편이 되면서 가짜 풀 증량이 최우선 과제다.

### 2-2. 프롬프트 설계 원칙 (게임의 핵심 자산)
실제 한국 아파트 작명 문법을 분해해 프롬프트에 주입한다:

```
[브랜드] + [지역/입지 키워드] + [펫네임] (+ [차수/블록])
 래미안     리버/센트럴/역명      포레/에듀/노블/퍼스티지
```

- **Few-shot에 실단지명 포함**: 실제 이름 20~30개를 예시로 주고 "이 문법을 따르되 실존하지 않는 이름"을 요구.
- **난이도별 생성 프로파일**:
  - 쉬움: 문법은 맞지만 조합이 과함 (펫네임 3개 연속 등) — 웃음 담당
  - 어려움: 실단지와 한 끗 차이 (실존 브랜드 + 그럴듯한 실존 지명 + 흔한 펫네임 1개) — 긴장 담당
- **금지 지시**: 실존 지역 비하 뉘앙스, 저급 언어유희, 실존 단지명 그대로 재조합 금지를 프롬프트 단계에서 1차 차단 (최종 차단은 §2-3 검증기).
- **지역 특화 가짜**: 별도 필드를 두지 않고, 이름 안에 든 지역 이름을 K-apt 동·자치구 토큰과 대조해 실행 시점에 판별한다(`lib/data.ts`). 구역을 골라 노는 동안 가짜만 딴 동네 이름을 달고 나오면 공짜 힌트가 되기 때문이다.
- **미구현(계획)**: 프롬프트 버전·생성 프로파일 기록, 그 기록으로 "어떤 프로파일이 잘 속이는지" 역측정하는 루프. 데이터 파일에 해당 필드가 아직 없다.

### 2-3. 자동 필터 (`npm run validate-pool`, 구현)
모든 가짜 × 모든 실단지를 대조한다. 하나라도 걸리면 exit 1.
1. **실존 일치 제거**: 공백 제거·소문자화 후 완전 일치.
2. **유사 일치 제거**: 편집거리(Levenshtein) ≤ 2 또는 토큰 일치율 ≥ 80%. "사실상 실존"인 가짜가 정답 시비를 만들기 때문. 편집거리 3~4는 실패가 아니라 **경고**로 출력한다.
3. **블랙리스트**: 지역 비하·비속어 계열. 코드에는 최소 시드만 두고 운영하며 추가한다.
4. **형식 검증**: 길이 2~20자, id·이름 중복 없음, 필수 필드(`name`·`hint`) 존재, 실단지 메타(`sido`·`sigungu`·`builtYear`·`households`) 결측 없음.

브랜드 오탈자("래미앙" 등) 탐지는 아직 규칙이 없다. 생성 단계 지시와 사람 검토에 의존한다.

### 2-4. 생성 힌트 문구 (구현)
정답 공개 화면의 "이건 AI가 지은 이름" 아래 한 줄 힌트를 생성 시 함께 만들어 `hint` 필드에 넣는다. 예: "실존 브랜드에 없는 조합을 붙였습니다", "펫네임이 하나 더 얹혔습니다". 힌트가 가짜의 트릭을 살짝 알려줘 학습 재미를 만든다. 공식전·무한 모드 O/X 판정 응답에 그대로 실려 나간다.

### 생성 시 지켜야 할 분포

실단지는 4~5자짜리(신당현대, 평창삼성)가 600건이 넘는다. 가짜가 화려한
브랜드+펫네임 조합으로만 채워지면 **길이 자체가 정답 힌트**가 된다. 짧고
단순한 형식(지역명 + 옛 건설사, 옛 표기 맨션·연립)을 반드시 섞는다.

## 3. 난이도 라벨링

| 난이도 | 진짜 문제 기준 | 가짜 문제 기준 |
|---|---|---|
| 쉬움 | 전국구 유명 단지, 단순 작명("OO주공1단지", "래미안OO") | 문법 파괴·과잉 조합으로 웃긴 이름 |
| 중간 | 브랜드+펫네임 1개의 평범한 신축 | 문법은 완벽하나 조합이 낯선 이름 |
| 어려움 | 펫네임 2개 이상의 실존 단지 ("이게 진짜라고?" 담당) | 실단지와 한 끗 차이 프로파일 |

- 실단지 라벨은 **수집 시 자동**: 펫네임 사전(포레·에듀·노블·퍼스티지 등 17개) 히트 수와 토큰 수로 판정한다. 펫네임 2개 이상 또는 토큰 4개 이상이면 `hard`, 펫네임 1개 또는 토큰 3개면 `mid`, 나머지는 `easy`. 현재 분포는 쉬움 2,491 / 중간 328 / 어려움 70으로 **쉬움에 크게 치우쳐 있다** — 난이도 커브의 `hard` 칸이 사실상 같은 70건을 돌려쓴다는 뜻이라, 어려움 라벨 보정이 다음 과제다.
- 가짜 라벨은 생성 시 수동 지정.
- **실측 재라벨링은 미구현**: `question_stats`가 `(date, no)` 단위라 문항 id와 연결되지 않아, 정답률을 개별 단지·가짜 이름에 되먹일 경로가 아직 없다. 집계 스키마에 항목 참조를 추가하는 것이 선행 조건이다.

## 4. 검수 프로세스 (사람)

> 운영 설계 전제: 검수·운영 프로세스는 Jessi 리드. 아래는 초기 제안 룰이며 운영하며 개정한다.

### 4-1. 현재 방식
- **관리 화면·검수 큐·반려 사유 태그는 전부 미구현.** 지금 검수는 수집본(`apartments.collected.json`) 파일과 신규 가짜 이름 목록을 직접 읽어 보고, `validate-pool`을 통과시키는 것으로 대체한다.
- 사람이 볼 때의 체크리스트는 그대로 유효하다:
  1. 실존처럼 들리는가? (게임 품질)
  2. 지역·집단 비하로 읽힐 여지가 없는가? (안전)
  3. 특정 실존 단지를 연상시켜 그 단지에 대한 조롱이 되지 않는가? (안전)
  4. 오탈자·어색한 조합이 없는가? (품질)
- 계획: 승인/반려/보류와 반려 사유 태그를 남기는 관리 화면. 사유 통계가 프롬프트 개선 입력이 된다.

### 4-2. 실단지 쪽 검수
가짜만 검수하는 게 아니다. 어려움 난이도로 나갈 실단지("이게 진짜라고?" 후보)는 명칭이 최신인지(개명·재건축), 메타데이터가 맞는지 승격 시 확인한다. "우리 동네 있는데요? 그거 이름 바뀌었는데요"가 최다 예상 클레임이기 때문.

## 5. 출제 운영

### 5-1. 현재 구조 (구현)
- **무한 모드가 본편**이다. 창구에 들어가면 곧바로 무한 세션이 시작되고, 출제는 풀 전체에서 매 요청 랜덤으로 뽑는다(`web/lib/endless.ts`). 사전 편성이라는 개념이 본편에는 적용되지 않는다.
- **데일리는 "제N호 공식전"**으로, 게임 안 칩으로 선택 참가한다. 문제는 테이블에 저장하지 않고 **KST 날짜를 시드로 결정적으로 생성**한다(`web/lib/daily.ts`, 조립 `assemble.ts`, 진짜 찾기 `findreal.ts`는 시드 오프셋으로 분리). 전원 같은 문제를 보되 저장소는 필요 없다.
- 공식전 구성 규칙: 진짜:가짜 = 4:6~6:4 랜덤, 난이도 커브는 위치별 `easy, easy, mid×5, hard×3`. 해당 난이도 후보가 모자라면 인접 난이도로 대체한다.
- 조립 모드 정답 풀은 **토큰 2개 이상으로 쪼개지는 실단지 272건**, 함정 조각은 가짜 이름에서 뽑은 **토큰 344종**이다.

### 5-2. 미구현 (기획 유지)
- **90일 재출제 금지**: `last_used_at` 같은 출제 이력이 없어 적용되지 않는다. `daily.ts`에 TODO로 남아 있다.
- **주간 편성 도구**: 7일치를 미리 편성하고 운영자가 교체하는 흐름. 날짜 시드 방식이 그 자리를 대신하고 있어 우선순위가 낮다.
- **편성 감각 규칙**: 하루 10문제에 "웃긴 가짜" 1개 + "이게 진짜라고?" 실단지 1개를 반드시 넣는 규칙. 지금은 난이도 커브만 있고 이 보장은 없다.
- **폴백 세트**: 편성 사고용 예비 문제 세트. 시드 생성 방식에서는 데이터 파일만 있으면 문제가 비지 않으므로 필요성이 낮아졌다.
- **오류 제보 처리**: 접수 창구·집계 제외 플래그 모두 미구현. 처리 플로우 설계는 [05 문서](05-growth-and-ops.md#3-운영-프로세스) 참조.

## 6. 파이프라인 요약도

```
[K-apt API] ─수동 실행─> [collect-kapt] ─> [apartments.collected.json]
```
