# 02. 게임 상세 기획

## 1. 코어 루프 화면 플로우

```
[홈: 접수 대장] → [창구 진입 = 무한 세션 즉시 시작]
       → (문제 → 판정 → 다음) 반복 → [판 종료] → [판정 통지서] → [도전장 보내기 / 한 판 더]
[홈 대장 현황 열] → (선택) [공식전 10문제] → [판정 통지서] → [통지서 공유]
[받은 도전장 /c/번호] → [같은 문제를 같은 순서로] → 첫 오답에서 끝 → [대결 통지서: 승리·무승부·패배]
```

> 첫 화면은 인트로가 아니라 **접수 대장 홈**이다. 전체 플로우와 계정·기록 설계는 [07. 플로우·계정·기록](07-account-and-records.md) 참조.

**본편은 무한이다.** 하루치 문제를 다 풀면 더 할 게 없는 구조는 게임을 스스로 닫는다. 창구에 들어가면 바로 세션이 시작되고, 경쟁은 누적 기록(레벨·최고 연속·콤보)과 판 단위 순위로 성립한다. 데일리 10문제는 **공식전**이라는 선택 참가 랭킹전으로 남아 있다.

**다시 오는 이유는 날짜가 아니라 사람이다.** 스낵 게임이라 "매일 새 문제"는 붙잡는 힘이 약했다. 그래서 화면에서 호수(제N호)와 "매일·오늘·내일" 투의 문구를 걷었고(공식전은 그대로 하루 한 판이다), 세 창구 모두에 **도전장**을 붙였다(§4-3).

### 1-1. 홈 (접수 대장)

- 순번 / 창구 / 현황 3열 서식. 각 행이 게임 하나다.
- 창구 칸에는 그 게임의 개인 기록 꼬리표가 붙는다 ("무한 감별 · 최고 연속 12").
- 현황 칸은 창구마다 다르다. 공식전이 있는 창구(감별 셋)에서는 눌러서 출전하는 자리다 —
  미출전이면 인주색 "출전하기", 출전했으면 "성적표" 도장. 공식전이 없는 창구(작명소)는
  지금까지 접수한 이름 수를 보여주고 기록 열람실로 넘긴다.
- 레벨 칩과 계정 상태 한 줄이 제목 아래에 조용히 붙는다.

### 1-1b. 공식전은 어디로 들어가나 (접수 대장의 현황 열)
무한을 본편으로 올리면서 공식전 입구가 "무한을 하다 보면 문제 줄 옆에 뜨는 작은 칩" 하나만 남았다.
만든 사람조차 출전 방법을 설명하지 못하는 상태였다. 입구를 홈으로 끌어올렸다.

- 접수 대장의 **현황 열이 그대로 출전구**다. 행 하나에 목적지가 둘이다:
  창구 이름을 누르면 무한, 오른쪽 도장을 누르면 그날의 공식전(`/o?official=1` 등).
- 도장 문구는 상태가 아니라 할 일을 쓴다: 아직이면 **출전**, 치렀으면 **성적표**.
  열 이름은 "현황"이다. 창구마다 현황의 뜻이 다르고, 공식전이 없는 창구까지
  "공식전"이라는 머리글을 이고 있으면 없는 것을 있다고 말하는 셈이 된다.
- 대장 아래 한 줄이 규칙을 직접 말한다(창구 이름 = 무한, 오른쪽 도장 = 같은 문제를 푸는 랭킹전).
- 무한 화면에서 공식전으로 건너가던 칩은 없앴다. 대장이 제 몫을 하게 된 뒤로는 같은 입구가 둘이 되고,
  무한을 치는 중에 공식전 회차가 떠서 지금 뭘 치고 있는지 헷갈렸다.

### 1-2. 문제 화면 (무한)

- 상단 한 줄에 판 상태: "무한 N번째 · 연속 X · 최고 Y". 도전장 판이면 그 자리에 상대 기록까지 남은 막대와 "N번째 · 연속 정답 X / 상대 Y"가 뜬다.
- 기록이 하나도 없는 사람의 **첫 문제에만** 규칙 한 줄이 뜬다. 한 번이라도 기록이 쌓이면 다시 보이지 않는다.
- 모드별 제한시간 바가 돈다. 시간이 다하면 자동 오답 제출.

| 게임 | 화면 | 제한시간 |
|---|---|---|
| 감별 O/X | 단지명 한 줄 + [진짜] [가짜] | 12초 |
| 이름 조립 | 위치·준공년도·세대수 힌트 + 조각 타일 + 정답 칸 | 40초 |
| 진짜 찾기 | 후보 4개 중 진짜 하나 고르기 | 15초 |

### 1-3. 정답 공개 (같은 화면에서 전환)

- **진짜였을 때**: "진짜 있는 아파트" + 메타데이터 한 줄 (`서울 서초구 반포동 · 2023년 준공 · 2,990세대`). 이 정보가 "이게 진짜라고?"라는 2차 재미와 댓글 논쟁의 소재다.
- **가짜였을 때**: "AI가 지은 이름" + 생성 힌트 한 줄 (가짜 데이터에 미리 저장된 문구).
- **진짜 단지에는 항공사진이 붙는다**(세 창구, 무한·공식전 모두). 칸 오른쪽 위 작은 사진(84px, 380px 이하 56px)을 누르면 덮개로 크게 보고, 거기서 카카오맵 단지 사진·로드뷰로 넘어간다. 항공사진만으로는 어느 건물인지 몰라서("이 아파트인지 알게 뭐야") 사진 정중앙에 인주색 핀을 찍는다. 크게 띠로 넣으면 320x568에서 '다음 문제'가 밀려서 작은 사진 + 덮개로 했다. 시안 `design/photo-a.html`.
- 무한에서는 연속·평균 시간·최고 기록이 한 줄로 따라붙고, 다음 문제로 넘어가거나 "여기까지"로 판을 끝낸다.
- 자동 넘김은 없다. 스크린샷 찍을 시간을 준다.

### 1-4. 조립 전용: 초성 힌트와 속도 점수

- 15초 / 25초 / 33초가 지나면 힌트가 한 단계씩 열린다. 단계마다 **조각 하나당 무작위 위치의 한 글자**가 열리고, 열리는 자리는 시드로 고정돼 단계가 올라가도 바뀌지 않는다. 앞에서부터 몰아 열면 첫 조각이 통째로 공개돼 버리기 때문이다.
- 힌트는 **정답을 넣는 칸 안**에 표시된다. 열린 자리는 글자, 가린 자리는 점 하나. 칸 폭이 곧 그 조각의 글자 수를 알려준다.
- 공식전 점수: `max(2, 10 + round(남은초 / 4) - 힌트단계 × 4)`. 빨리 맞힐수록 높고 힌트를 본 만큼 깎인다.

### 1-5. 결과 화면 (판정 통지서)

확정 시안 `design/result3-r1-verdict.html`.

- 등급 도장이 주인공이다. 크게, 기울여 날인한다.
- 수치는 전부 순번 괘선 서식표 한 장에 접어 넣는다. 판정 그리드 / 기록 / 순위 / 감별사 등급 순.
- 무한 세션: 판정 · 세션 기록(연속·평균) · 역대 기록(신기록이면 인주색) · 판 순위(최근 7일 상위 %) · 감별사 등급.
- 공식전: 판정 · 전국 순위 · 연속 출전 · 감별사 등급. 조립은 조립 점수 행이, 진짜 찾기는 콤보 행이 추가된다.
- 무한 판: 판정 · 판 기록 · 역대 기록 · 판 순위 · 감별사 등급, 그리고 **도전장 보내기**(통지서 이미지 공유 자리를 이어받았다).
- 검은 버튼은 화면당 하나뿐이다(공식전은 통지서 공유, 무한은 도전장 보내기). 나머지는 고스트 버튼.

## 2. 출제 로직

### 2-1. 무한 (본편)

| 규칙 | 내용 |
|---|---|
| 출제 | 판마다 시드를 두고 n번째 문제를 (시드, n)으로 정한다(`lib/run.ts`). 구역마다 겉모양 무게로 뽑는다(`lib/balance.ts`). 서버가 정답을 쥐고 판정한다 |
| 횟수 | 제한 없음. 세션은 사용자가 끝낼 때까지 이어진다 |
| 기록 | 연속, 최고 연속(진짜 찾기는 콤보), 평균 풀이 시간 |
| 판 순위 | 세션 종료 시 최근 7일 다른 판들과 비교한 상위 %. 표본 20판 미만이면 "집계 중" |
| 이탈 | 결과를 안 보고 떠나도(공식전 전환·로고 클릭) 그 판은 집계와 경험치에 접수된다 |

### 2-2. 공식전 (선택 참가 랭킹전)

| 규칙 | 내용 | 이유 |
|---|---|---|
| 전원 동일 문제 | 날짜(KST) 기반 데일리 시드로 10문제 생성 | "오늘 8/10" 인증이 성립하려면 문제가 같아야 함 |
| 갱신 시각 | 매일 00:00 KST | 자정 갱신 대기 문화 |
| 하루 1회 | 완주 후 재출전 불가. 대장의 같은 칸이 "성적표" 도장으로 바뀌어 결과를 다시 연다 | 희소성이 랭킹전의 전제 |
| 첫 답이 최종 답 | 같은 문제를 다시 보내면 첫 판정을 그대로 돌려주고 집계에 넣지 않는다(`lib/officialrun.ts`) | 진짜를 눌러 보고 틀리면 가짜로 다시 눌러 만점을 칠 수 있었다 |
| 진짜:가짜 비율 | 4:6 ~ 6:4 사이에서 매일 랜덤 | "항상 5:5"면 후반에 개수 세기 메타가 생김 |
| 난이도 커브 | 쉬움 2 → 중간 5 → 어려움 3 | 초반 성공 경험으로 몰입, 후반의 "이건 모르겠다"가 공유 욕구를 만듦 |
| 집계 | 문제별 정답률, 점수 분포(상위 %). 표본 100명 미만이면 비표시 | |
| 재출제 금지 | **미구현.** 동일 단지명 90일 재출제 금지가 목표 | 매일 하는 유저가 문제를 외우는 것 방지 |

난이도 라벨링 기준은 [03. 데이터·콘텐츠 파이프라인](03-content-pipeline.md#3-난이도-라벨링)에서 정의.

## 3. 등급과 레벨

### 3-1. 등급 도장 (한 판의 판정)

모드마다 등급표가 따로 있다. 감별 O/X 기준:

| 점수 | 등급명 | 카드 문구 |
|---|---|---|
| 0~3 | **외지인** | "아파트 이름이 다 그게 그거 같죠? 정상입니다." |
| 4~6 | **모델하우스 구경러** | "발품은 팔아봤는데, 이름까진 안 외웠군요." |
| 7~8 | **부동산 카페 눈팅러** | "매일 눈팅한 짬은 못 속입니다." |
| 9~10 | **시어머니도 못 찾는 이름 감별사** | "이름만 봐도 평면도가 보이는 수준." |

- 이름 조립은 건설 현장 콘셉트(함정 조각 수집가 → 견습 조립공 → 현장 반장 → 설계도 없는 건축사), 진짜 찾기는 눈썰미 콘셉트(AI의 단골 손님 → 모델하우스 단골 → 공인중개사 뺨치는 눈 → 부동산 매의 눈).
- 무한 세션은 점수표 대신 세션 성적으로 도장을 찍는다(신기록 갱신 / 상급 감별 / 감별 수련 / 재수련 요망).
- **등급명 정책**: 주거 형태·주거 불안정(전세·월세·무주택 등)을 소재로 한 명칭 금지. 놀림의 대상은 항상 "아파트 작명 문화"이지 유저의 주거 상황이 아니다.

### 3-2. 감별사 레벨 (날짜를 넘는 성장축)

- 모든 게임의 정답이 경험치가 된다. 무한 정답 5점(조립은 8점), 세션 신기록 30점, 공식전은 정답 10점 + 완주 20점.
- 레벨에는 상한이 없고, 직급은 접수처 세계관을 따른다(견습 감별사 → 감별 주무관 → 주임 → 계장 → 과장 → 국장 → 수석 감별관 → 감별 명장).
- 결과 화면과 홈 칩에 노출된다. 로그인하면 기기를 넘어 이어진다.

## 4. 공유

### 4-1. 접수증 이미지 카드 (공식전)

확정 시안 `design/share3-s2-receipt.html`. Canvas 2D로 1080×1350 PNG를 그린다. 공식전 통지서에서 쓴다(무한 판은 §4-3 도전장).

- 창구에서 뽑아준 영수증 한 장이 콘셉트다. 위아래 절취 지그재그, 점선 괘선으로 나뉜 항목 열거, 판정 타일 한 줄, 등급 도장과 APPROVED, 판마다 무늬가 고정되는 시드 바코드, 붉은 주소 한 줄.
- 접수 관인은 마지막에 종이 **위에** 찍는다. 바코드를 왼쪽으로 물려 오른쪽에 도장 칸을 비워 뒀다.
- 모바일은 시스템 공유 시트, 데스크탑은 파일 다운로드로 떨어진다.
- **판정 그리드는 이모지가 아니라 그래픽으로 그린다.** 이 원칙은 화면과 카드 모두에 적용된다.

### 4-2. 공유 랜딩과 OG

- 결과 링크(`/r/{슬러그}`)는 공식전 점수·등급·판정 그리드를 통지서 서식으로 보여주고, 창구로 유도한다.
- OG 미리보기 이미지는 같은 정보로 동적 생성한다. 사양은 [04. 기술 사양](04-tech-spec.md) 참조.

### 4-3. 도전장 (구현, 세 창구 모두)

무한 판 결과는 이미지 대신 **도전장 링크**(`/c/번호`)로 나간다. 통지서를 보여 주는 것은 자랑에서 끝나지만, 도전장은 받은 사람을 같은 문제 앞에 앉힌다.

- 받은 사람은 보낸 사람의 최고 연속이 시작된 번호부터 **같은 이름을 같은 순서로** 받고, 처음 틀리는 문제에서 끝난다. 진짜 찾기는 보기 순서까지, 이름 조립은 미끼 조각과 조각 순서까지 같다.
- 보낸 기록을 넘으면 **승리**, 같으면 **무승부**, 못 넘으면 **패배**. 기록은 "N문제 연속 정답"으로 풀어 쓴다 — "연속 2 · 분패"라고 썼더니 무슨 말인지 하나도 모르겠다는 반응이었다.
- 이긴 쪽은 자기 기록으로 새 도전장을 보내고("내 기록으로 도전장 보내기"), 진 쪽은 새 판을 쳐서 보낸다. "같은 문제로 다시 도전"도 있지만 **답을 본 판**이라 경험치를 주지 않고 그 기록으로 도전장도 못 보낸다(보낸 사람이 자기 도전장을 쳐 보는 것도 같다). 가상 사용자 둘로 쳐 보니 아는 문제를 되풀이해 한 판에 237점을 받았다.
- 기록은 서버가 센 판에서만 나온다. 요청에 숫자를 싣지 않는다. 받은 사람 결과는 한 사람의 첫 판만 센다.
- 보낸 사람은 기록 열람실에서 보낸 수 · 받아 친 사람 · 넘은 사람을 본다. 링크 미리보기는 "N문제 연속 정답"과 창구 이름을 그린다.
- 시안 `design/challenge-a.html`.

## 5. 리텐션 장치

**구현됨**

1. **무한 세션의 장력**: 연속이 끊기는 순간이 곧 "한 판 더"의 이유다.
2. **판 순위**: 세션이 끝나면 최근 7일 다른 판들과 비교한 상위 %가 나온다. 어제의 나와 남을 동시에 이기는 축.
3. **누적 레벨과 직급**: 날짜를 넘어 쌓이는 성장. 홈에서 항상 보인다.
4. **연속 출전**: 공식전 완주로 쌓이는 스트릭.
5. **성적표 재열람**: 오늘 친 공식전 결과는 언제든 다시 열 수 있다.
6. **도전장**: 받은 도전장이 있으면 오고, 보낸 도전장을 누가 넘었는지 보러 온다. 날짜가 아니라 사람이 부르는 복귀 장치다.

**계획 (미구현)**

7. 오답 복기 화면.
8. 주간 리캡("이번 주 평균 7.2/10, 상위 18%").
9. 연속 출전 7일/30일/100일 특수 배지.

## 6. 늦게 연 창구와 구역

### 6-1. 작명소 (4번 창구, 전개)
사람이 가짜를 짓는 창구다. 초안은 "조각 드래그 + 투표 + 명예의 전당"이었는데, 투표 대신 **속은 사람 수**로 겨루는 쪽으로 바뀌었다 — 지은 이름이 감별 창구에 가짜로 나가고, 몇 명을 속였는지가 작명 점수가 된다. 감별 셋과 방향이 반대라 첫 화면이 "왜 하는가"부터 말한다.

- 구역을 먼저 고르고(아파트 이름의 절반은 동네 이름이다) 그 구역의 실제 동 이름과 공용 조각 어휘로 짓는다. 조각 어휘는 실단지에서 실제로 쓰이는 것을 세어 뽑았다(`lib/naming.ts`).
- **로그인해야 쓸 수 있다.** 지은 이름이 남들의 문제로 나가는 생산이라, 누가 지었는지 알아야 "몇 명이 속았는지"를 돌려줄 수 있고 하루 몇 건인지 셀 수 있다. 막는 자리는 첫 화면이다.
- 실존 대조는 서버에서만 한다. 하루 20건 접수, 점수는 하루 5건까지(한 건 12점).
- 말 거르기로 세 갈래(거부 · 대기 · 자동 승인)가 되고, 승인된 이름은 매일 05:10 야간 작업이 출제 풀로 내보낸다. 단계는 화면에 그대로 보인다(검토 중 · 출제 대기 · 출제 중 · 반려).
- 작명 호칭은 감별 직급과 갈라 둔다. 합치면 이름을 많이 지은 사람이 구역 명부 순위로 올라간다.
- 상세는 [03. 파이프라인](03-content-pipeline.md#4-검수-프로세스)과 [06. 게임 모드](06-game-modes.md).

> 주의: "이름 조립" 창구와 다르다. 조립 창구는 실존 단지명을 복원하는 퍼즐이고, 작명소는 가짜를 만드는 창구다.

### 6-2. 담당 구역 고르기 (구 "우리 동네 모드", 1단계로 앞당겨 개설)
별도 창구를 세우지 않고, 홈 접수 대장 위의 **담당 구역** 칸으로 붙였다. 창구를 하나 더 만들면
"어디로 들어가야 하지"가 늘어날 뿐, 하는 일은 같은 게임에 출제 범위만 좁히는 것이기 때문이다.

- 기본값은 `전국 · 무작위`. **시·도 15곳**(광주·전남 제외 전국)을 고르면
  **세 창구 모두** 그 범위 단지만 낸다. 선택은 `aptgam:area`로 기기에 남고,
  게임 헤더에 `무한 감별 · 부산`으로 지금 범위를 계속 알린다.
- **자치구 단위는 두지 않는다.** 한때 서울만 자치구를 열었는데, 그러면 두 가지가 어긋났다.
  ① 전수 수집이 끝난 곳이 서울뿐이라 "왜 여기만 구가 있지"가 생긴다.
  ② 조립 퍼즐은 이름에 공백이 있어야 조각이 되는데 그런 단지가 전국에 677곳뿐이라,
  자치구로 쪼개면 한 구에 3~20곳(강북구 3곳)이다. 그래서 조립만 시·도로 넓혀야 했고
  창구마다 적용 범위가 갈렸다. 시·도 하나로 맞추니 설명할 것이 없어졌다.
  시·도 단위 조립 퍼즐 수는 제주 24곳 ~ 서울 259곳이다.
- **가짜도 같이 좁힌다.** 진짜만 그 동네 이름이면 "낯선 동네 이름 = 가짜"라는 공짜 힌트가 생긴다.
  그래서 가짜 이름에 들어 있는 지역 이름(K-apt 단지의 동·자치구 이름에서 뽑아낸 토큰)이
  고른 범위와 맞을 때만 쓴다. 지역색이 없는 이름은 어디서나 쓴다. 조립의 함정 조각도 같은 규칙이다.
  지역 토큰은 `시도|시군구` 복합키로 잡는다. 구 이름만 쓰면 서울 중구와 부산 중구가 한 키가 되어
  "중림진달래"가 부산 문제로 새어 나온다(실제로 겪고 고쳤다).
- **공식전도 구역을 따른다.** 처음에는 전국 공통으로 두었다. "전원이 같은 문제를 풀어야 순위가
  성립한다"는 이유였는데, 그 전제가 틀렸다. 비교 단위를 전국이 아니라 **(날짜, 구역)**으로 잡으면
  같은 구역 참가자끼리는 여전히 같은 문제를 푼다. 순위는 그 안에서 계산하면 된다.
  구역은 문제에 나오는 단지의 지역이지 푸는 사람의 거주지가 아니므로, 지역 비하 우려와도 무관하다.
  - 시드에 구역 해시를 섞어 구역마다 다른 10문제를 낸다 (`lib/seeded.ts: areaSeed`).
  - 집계 테이블의 기본키가 `(date, area, mode, …)`가 됐다. 전국 공식전은 `area = ''`.
  - **창구(mode)도 집계 키다.** 세 창구는 문제가 완전히 다른데 예전에는 한 칸을 함께 써서
    조립 1번과 감별 1번의 정답률이 한 행에 합산됐다. 게다가 조립·찾기는 기록 호출 자체가 없어
    공식전 순위가 나오지 않았다 — 이번에 `/api/assemble/finish`·`/api/findreal/finish`를 만들고
    판정 라우트에 집계를 붙였다.
  - 화면 이름도 구역을 밝힌다: `부산 공식전`, 순위 칸은 `부산 순위`.
  - 클라이언트가 보낸 구역 값은 `isArea`로 거르고 모르는 값은 전국으로 떨어뜨린다.
    임의 문자열이 집계에 쓰레기 구역을 만들면 순위가 조각난다.
- **구역끼리 줄 세우지 않는다.** 지역 랭킹·지역 평균 비교는 만들지 않는다. 어느 동네가 더 어렵다는
  이야기가 붙는 순간 게임이 아니라 시비가 된다 ([05. 리스크](05-growth-and-ops.md#4-리스크-및-대응)).
- 남은 구멍: 아파트가 한 곳도 없는 동네(체부동·누상동 등)의 이름은 토큰에 안 잡혀 지역색 없는 이름으로 남는다.
  틀린 답을 만들지는 않지만 메우려면 법정동 전체 표가 필요하다.
- 남은 구멍: 광주(29)와 전남(46)은 K-apt 목록 API가 계속 빈 응답이라 없다. 이웃 시도는 모두 정상이라
  상류 데이터 구멍으로 본다. 나머지 15곳은 받을 수 있는 것을 다 받았고, 새로 생기는 단지는 야간 작업이 매일 받는다.

## 7. 톤 앤 매너

- **카피 톤**: 접수 창구의 공문서 화법 위에 부동산 커뮤니티 밈 감각을 얹는다. 진지한 부동산 정보 서비스처럼 보이면 실패다. 단, 특정 지역·단지·거주자를 비하하는 유머는 금지 ([05. 리스크](05-growth-and-ops.md#4-리스크-및-대응) 참조).
- **비주얼**: 텍스트(단지명)가 주인공. 도장·괘선·관인이 세계관을 만든다. 로고·BI·조감도 등 브랜드 자산은 절대 미사용.
- **효과음**: 도장 날인, 연속 상승, 제한시간 임박 초침, 시간 초과 부저, 힌트 공개, 신기록까지 전부 Web Audio로 합성한다(오디오 파일 없음).
- **배경음**: 게임 화면에서만 아주 낮게(6%) 흐르는 58초 심리스 루프. 헤더 스피커 버튼으로 끄고, 끈 선택은 기기에 남는다. 효과음이 울리는 동안에는 배경음이 잠깐 몸을 낮춘다. 홈과 기록 열람실에서는 나오지 않고, 첫 터치 전에는 파일도 받지 않는다.
- **배경음 시행착오**: 직접 생성한 다섯 갈래(로파이 앰비언스, 90년대 관공서 대기음, 8비트, 뽕짝)는 전부 반려됐다. 사유는 음질이 아니라 "게임이 재미있어 보이지 않는다"였고, 결국 사람이 고른 곡으로 교체했다. 곡 선택이 재생 기술보다 어려운 문제였다는 기록으로 남긴다.
